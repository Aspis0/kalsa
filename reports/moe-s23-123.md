### 1.3 Is implementing skip-when-peaky justified?

**No.** Three independent reasons, any one of which is enough:

1. **Coverage.** 97.4 % of decode (step, layer) cells have top-1 share
   &lt; 0.50. At 0.70 the rule fires once in 1600. There is nothing to
   skip as a policy.
2. **Already dropped.** `--drop-cold-experts 0.65` already removes more
   average slots than the peaky rule would. The extras on a peaky cell
   are the small-weight ones drop-cold already targets.
3. **Quality proxy failed.** Global k=1 (the extreme of "skip extras
   always") EOGd at step 0 on this prompt. That is not a measurement of
   a *conditional* skip, but it is a hard stop on treating k=1 as
   "almost k=6".

A teacher-forced k=1 vs k=6 PPL (`--ppl-decode`) would still need PC
quality if someone reopened this. It is not justified by this trace.
**DEAD.**

## 3. Idea3 — in-RAM vs disk hybrid save — **BLOCKED_ENGINE**

Question: can we persist the hybrid (attn KV + recurrent/SSM) state to
disk so the next process skips prefill? What exists today, and why is
hybrid save missing?

### 3.1 What `--session` actually is (in-RAM)

`--session` (`cli/main.cpp:369`, `656`) keeps **one process** up and
reads JSON generates from stdin. The expert LRU survives. That is RAM.
`Session` (`session.h:104-196`) has `open`, `generate`, `perplexity`,
`perplexity_decode`, `cancel`, `set_cache_budget_mb`. **No save. No
load.** `--cache-mb` is the expert LRU, not a KV persist path
(`print_usage` at `main.cpp:443`; device `--help` 18 save/load/cache
hits, all expert-cache / mmap / `--load-all` / `--session`).

Cell E: `--session`, **no `--chatml`**, two JSON turns
(`idea3/E/t1.json`, `t2.json`). READY:
`think_ctl=template`, `n_expert_used=6`, `load_s=20.567`.

| id | tokens | tok/s | n_prompt | n_past | prefill_s | text |
|---:|---:|---:|---:|---:|---:|---|
| 1 | 0 | 0.000 | 75 | 75 | 14.791 | empty (first token EOG) |
| 2 | 16 | 2.130 | 100 | 116 | 18.834 | `<think>…` + trade-off sentence |

`BMOE_DONE` has **no `n_common` key** (`idea3/E/kv_fields.json`:
`n_common_in_schema=false`, grep `[]`). Do not invent `n_common=16`
(`116-100` is `n_gen`) or `n_common=75`.

Engine (`session.cpp`):

```1167:1173:BigMoeOnEdge/core/src/engine/session.cpp
    // Reuse the KV prefix already decoded from earlier turns (chat mode only)
    size_t n_common = 0;
    if (chat_on && !im.kv_tokens.empty()) {
```

`chat_on` is set only under `--chatml` (`session.cpp:658-661`). E did
not pass `--chatml`. `n_common` stays 0. Accounting
(`session.cpp:1629-1630`):

- `n_prompt` = tokens actually prefilled this turn (`n_prompt - n_common`)
- `n_past` = `chat_on ? kv_tokens.size() : n_prompt + n_gen`

Plug in `!chat_on`: T1 `75 = 75 + 0`. T2 `116 = 100 + 16`. Holds.
T2 prefilled **100** tokens in 18.834 s at 5.31 tok/s, same rate as
T1's 14.791 s / 75 tokens / 5.07 tok/s. A reused prefix of 75 would
have prefilled ~25 tokens (~5 s), not 18.8 s. **Reuse did not happen.**
`--session` without `--chatml` is "keep the process and the expert
cache", not "stack the KV".

T1 EOG is the extra newline after `Assistant:` (361 vs 360 bytes vs
A). Do not treat T1 as a successful gen. `cells.csv` row E is turn 2
only (`parse_oneshot` keeps the last `BMOE_DONE`).

`n_rs_seq` (`session.cpp:701-704`) is **speculation rollback**, not
disk save. Qwen3.5/3.6 hybrid supports recurrent snapshots
(`llama-arch.cpp:966-973` `llm_arch_supports_rs_rollback` true for
`LLM_ARCH_QWEN35` / `LLM_ARCH_QWEN35MOE`). That path is in-RAM draft
reject.

Hybrid `seq_rm` (`llama-memory-hybrid.cpp:143-149`) tries the
**recurrent** cache first and can refuse a partial remove; session then
clears the whole KV (`session.cpp:1180-1182`). Mid-sequence rewind is
not a safe typeahead primitive on this model. Already measured dead
for typeahead in `reports/moe-s23-idle-ideas.md`.

### 3.2 Why hybrid disk save is missing (file:line)

llama.cpp **can** serialize this hybrid. bmoe **never calls it**.

API present, unused:

```821:846:BigMoeOnEdge/third_party/llama.cpp/include/llama.h
    LLAMA_API bool llama_state_load_file(...);
    LLAMA_API bool llama_state_save_file(...);
```

`llama_context::state_save_file` writes magic + token list +
`memory->state_write`. For Qwen3.6 hybrid memory:

```190:194:BigMoeOnEdge/third_party/llama.cpp/src/llama-memory-hybrid.cpp
void llama_memory_hybrid::state_write(...) {
    if ((flags & LLAMA_STATE_SEQ_FLAGS_PARTIAL_ONLY) == 0)
        mem_attn->state_write(io, seq_id, flags);
    mem_recr->state_write(io, seq_id, flags);
}
```

That is attn KV **plus** recurrent/SSM. Enough to restore transformer
memory. It is **not wired**.

Repo grep of `BigMoeOnEdge/core/` and `BigMoeOnEdge/cli/`: **zero**
calls to `llama_state_save_file` / `llama_state_load_file` /
`llama_save_session_file` / `llama_load_session_file`. Device `--help`
has no `--save`, `--load-session`, `--save-session`, `--load-kv`,
`--save-kv`. Master log: `E help has no --save/--load session flag
(cache-* is the expert LRU, not KV persist)`.

Missing because **bmoe never exposed the existing llama.cpp API**, not
because hybrid `state_write` is absent, and not because Qwen3.6 cannot
serialize. `common.cpp:2045` and `tools/completion/completion.cpp:986`
call `llama_state_save_file` in **llama-cli / completion**, not in
`bmoe-cli`.

Even if someone called `llama_state_save_file` tomorrow:

1. **Expert LRU is not in the llama state.** After load you re-pay the
   cache warm ramp (`docs/session.md`). Disk KV does not replace
   `--session` for flash MoE.
2. **bmoe `kv_tokens` / `chat_history` are engine-side.** A raw llama
   file does not restore chat-mode prefix match.
3. **No `--chatml` means no prefix match anyway** (`session.cpp:1172`).

Disk save: **not possible today via this binary.** In-RAM `--session`
works as a process. That is the whole distinction. **BLOCKED_ENGINE.**

No session file was written. Do not treat cell E as a disk I/O
measurement.
