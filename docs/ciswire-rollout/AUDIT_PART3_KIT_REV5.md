Bottom line: **FIX-AGAIN, three structural items before build.** (1) The compaction "on" flag value
is a silent wrong-regime trap — `"1"/"on"/"true"` maps to **anchored** (no digest, no KALSA_DIGEST,

mis-set arm. (2) **There is no conversation script**: no planted facts, no tool-request turns, no

contrasts are well-powered and the 2³ was the right call; the *reporting* granularity ("deltas vs
R1" at n=3/6) is noise, and 'no significance' bites exactly at the effect sizes type-axes
plausibly have — the floors are computable now and must be printed.

## 2. The arithmetic (exact)

- Permutation floors (min two-sided p at n vs n): n=3 → 2/C(6,3) = **0.100** (single cell, never significant); n=6 → 2/C(12,6) = **0.00216**; n=12 → 2/C(24,12) = **7.4e-7**; n=24 → 2/C(48,24) = **6.2e-14**.
- 80 % power (two-sided, α=0.05): δ = 2.802σ·√(2/n): n=3 → 2.29σ · n=6 → 1.62σ · n=12 → 1.14σ · n=24 → 0.81σ.
- Binary profile axes, conversation-level sd (24 turns): p=0.05 → sd 0.045 (Δ80 pooled 3.6 pp / variant 5.1 pp / arm 7.2 pp / **cell 10.2 pp**); p=0.2 → sd 0.082 (6.6 / 9.3 / 13.2 / **18.7**); p=0.5 → sd 0.102 (8.3 / 11.7 / 16.5 / 23.3). 95 % CI of a §8 "delta vs R1" cell: **±13.1 pp at n=3, ±9.2 pp at n=6** (p=0.2 axes).
- Recall axis, δ=+0.635 vs σ∈{0.083, 0.2, 0.35}: power n=12 = 1.00/1.00/0.99; n=24 = 1.00/1.00/1.00. The flagship contrast is safe at both variants; the per-arm "vs R1" reading (n=6, power 0.88 at σ=0.35) is the fragile one.
- Power at plausible type-axis effects: 0.5σ → 14 % (n=6) / 23 % (n=12) / 41 % (n=24). +5 pp echo at sd 0.082 (0.61σ) → 25 % / 45 % / 74 %.
- Holm families: m=15 primaries, first-rank α=0.0033 → detectable δ80 = 1.09σ pooled / 1.54σ per variant. m=90 (everything tested) → 1.24σ / 1.75σ. So "Holm where tested" only works if the family is pre-registered small; the rest must be exploratory-with-floors, not Holm'd.
- Wall-clock (information only; owner accepted): Jelly 2.6B decode 7.2→5.5 tok/s (−24 % in-session, §7.42), warm prefill 1.7-3.2 s, cold prefill ≈190 s. Thinking-on turn ≈ 1.5-2.5 min warm. Every window trim (cadence-3 in ciswire, 20-msg cap in off, winbudget in A) = full re-prefill (LFM2.5 cannot roll back; "a tool call costs the whole cache — 3 s → 195-405 s", §7.15-area): A-variant conversations plausibly **2-4 h**, B **40-90 min**; 48 conversations ≈ **45-110 h device time ≈ 2-5 device-days**, 1.5-3+ wall weeks supervised. Phase 0 must measure post-eviction per-turn cost before committing the 24 A-variant conversations — that number sets the schedule and the per-turn timeout.

## 3. Answers to the six audit questions

1. **Statistics.** Pooled factor contrasts are the only testable units: n=24/side, floor 6.2e-14, δ80 = 0.81σ; per-variant n=12, δ80 = 1.14σ. Recall (the flagship) is powered ≥0.99 even per-variant. Arm×variant cells (n=3, ±13 pp CI) and arm-level deltas (n=6, ±9.2 pp) are descriptive noise; §8's delta-vs-R1 format invites quoting them. 'No significance needed' bites at 0.5-0.6σ type-axis effects (23-45 % per-variant power): a real shift will read "no change" — the kit's "absence of evidence" clause is correct but must be made numeric: Phase-0 σ estimates → printed per-axis detection floors → CIs on every delta → conversation as the unit, never turn-level pooling.
2. **Info/axes.** Verdict: the profile captures verbosity + negative markers; 4/11 axes are length, counts are unnormalized, and the positive type-axes are missing: citation-of-context, question-asking back, in-session degradation slope. Without script-planted events (facts, probes, tool requests), echo/recall/drift/tool axes are structurally all-zero. "Unsupported numeric claim rate" is a judge-shaped task masquerading as deterministic.
3. **Harness/charging.** Charging does not invalidate the intended comparison (logical channels are clock-free); timing fields must be stamped invalid. The real on-charge risks: more SEVERE-thermal mid-conversation stops (resume semantics must be pinned and retried turns flagged) and thermal-driven hung generations (watchdog missing). Logcat as specced is blind to crash stacks and rotates during adb drops; the RKStorage pull path is proven and the per-turn datastore is the right primary.
4. **Recovery.** Crash poll OK; hung-generation gap is not. Wifi-adb reconnect needs offline/unauthorized handling and a logcat dump on every reconnect. Reinstall -r is right and models survive it (internal storage) — never uninstall/pm clear. Flag-switch sql_write requires the app force-stopped (missing from Phase 0). Restore 1.8 s is a different model's figure; expect seconds for 2.6B.
5. **Reusability.** Half-true: flags-as-key-value, device/model/counts, datastore layout and supervisor are generic; variants/params are not expressible in the config (this campaign's own A/B isn't in it), scorer names leak this campaign's instruments, and per-prefix telemetry semantics (absent=0, sentinel −1, digest-on-ciswire-only) need a schema or future campaigns mis-parse. A miniapp campaign would need harness edits today.
6. **All-combinations integrity.** The grid itself is intact (flags independent, re-read per turn — C4). The traps are *within* legs: F1 (on→anchored), F4/F5 (variant semantics asymmetric and misdescribed), F10 (calendar structurally inert without memory — still estimable), F9 (tool events model-gated). Each is fixable in the spec/report layer; none breaks the 2³ combos.
