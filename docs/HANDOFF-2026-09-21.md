## The audit of step 3b, and what the pixels added (2026-09-21)

The frozen range `9164feb..8ca312a` was audited by the Reviewer (GLM) against an **extraction**
(`git archive` → `/tmp`), so the capture agent's live edit never entered a result. Baseline
reproduced exactly: `tsc` clean, **110 suites / 1461 tests**, `markdownHarness.mjs` 151 PASS. Plus 48
adversarial parser probes with reconstruction oracles, a timing battery, and 12 deliberate
corruptions of the source files to test whether the guards can actually fail. **Verdict: ship.** The
parser lost, duplicated and reordered nothing in any probe (closer indented 0–3 closes and 4 does not,
4-backtick opener with a 3-backtick closer stays open, 1000-column table, 160k-char document linear,
CRLF mixed with LF, unclosed fence at the end of a stream).

**F1 — must fix, and it is a defect in the proof inventory rather than in the product.**
`transcriptMarkdownSource.test.ts:79-81`'s `scrollViewIsGatedOnTheDecision` is two unanchored
regexes, and the second one is satisfied by the **code block's** `<ScrollView horizontal>` at
`TranscriptMarkdown.tsx:225`. The auditor **deleted the table's entire scrolling branch** — the exact
defect §2.2 forbids, wide tables clipped and the third column unreachable — and the suite stayed
**9/9 green**. Every other guard was corrupted and went red; this is the single exception. Fix: run
both regexes over the `TableBlock` slice only, and add a negative sample that keeps a horizontal
`ScrollView` elsewhere in the file.

**F2 — measured, bounded, not a regression.** `TranscriptMarkdown.tsx:68` memoises on `[text]`, which
saves re-parses on unrelated renders but not during streaming, where `text` changes per token: the
whole document is re-parsed per token, so the cost is O(N²) in final length. One parse is linear,
about 35 ns/char in node; the last 2 000 characters of a 20 000-character answer cost ~251 ms over
501 parses. The engine's own prompt asks for under 200 words (`en.ts:1158`), which is ~25 µs per
token, so this is a note for the day answers grow — the fix would be coalescing text updates to one
parse per frame, with no parser change.

**F3, F4 — cosmetic, recorded not fixed.** A fence inside a blockquote (`> ```js`) stays quote text
because `markdownDocument.ts:20` allows at most 3 leading spaces; no text is lost, only fidelity. And
`TranscriptInline.tsx:146` keys the citation testID on the citation *number*, so `[2] … [2]` in one
paragraph yields two nodes with one testID — automated queries only.

### The hygiene block — paste this into EVERY coder brief

The owner asked for this explicitly, so it is written down once and repeated verbatim from now on. A
brief that omits it produces code that passes tests and still has to be cleaned by hand:

- **Clean code, and less of it than the code it replaces.** If a slice produces more lines than the
  thing it replaces, say why in the report.
- **Size: aim for ≤ 350 lines per file, 500 is the absolute ceiling** — a file at 500 is a file that
  should have been cut. The three ratchets in `src/host/fileSize.test.ts` are the floor of this rule,
  not the target: `src/host` ≤ 350, `HostRoot.tsx` ≤ 250, `src/ui/shell` ≤ 342, and they only ever go
  **down**. Never raise a number to make room; cut a seam and report it.
- **No God files.** One responsibility per file; the root composes and holds nothing but composition.
- **Imports: as few as possible, and as narrow as possible.** Type-only imports where only a type is
  used; no barrel/re-export files; no importing a module for one helper that belongs beside its
  caller; never import a component's neighbour to reach a constant — move the constant.
- **Comments: only for a WHY that is not obvious, or for a trap.** One or two lines. No narration, no
  history, no essays, no `path:line` citations in code (the documents carry the history), no
  commented-out code, no section banners for the sake of it. If a comment needs more than ~8 lines,
  the reasoning belongs in `docs/DESIGN.md`, `docs/PARITY.md` or the handoff, and the code gets one
  line pointing at it. **A comment that restates what the next line does is deleted, not shortened.**
  The measured state this rule replaces: `src/host` had 2,530 comment lines against 9,288 code lines
  (0.27) and `src/ui/shell` had 2,335 against 5,337 (**0.44**), with one file opening on a 94-line
  header.
- **Dead code is deleted, not commented out.**

called `suggestion1` fired `suggestion3` — so a card must be scrolled fully into the strip and its box
taken from a same-second dump before a tap is trusted; a controlled re-test found no hit-test defect in
the app. And the menu's **caption row is not a dismiss path** (it is informational, `clickable=false`);
the sheet's three cancellations are the backdrop, the Cancel row and BACK, and a brief that lists the
caption among them is wrong.

**One behaviour found that the parity documents do not mention, and that this project should not accept
quietly: tapping a suggestion card discards text already typed in the field.** The capture typed
`hello kalsa`, tapped a card, and the field went back to its placeholder while the bubble carried the
card's prompt. This project's own history is explicit about losing the user's words — the foreground-idle
marker in `App.tsx` exists because a fix once "removed the user's words while keeping the counters" — so
whether the controller did the same or whether this is new, a card tap must not silently eat a draft.

## Decisions that must not be silently reversed

- The palette is **green**; the dead `notebook` palette was deleted.
- **The transcript grows from the top while it fits and sticks to the bottom once it overflows.** A
  short conversation keeps its empty space — the owner chose the desktop behaviour explicitly.
- **One list entry per message**, created when an answer starts and never re-created, because a
  placeholder born in one place and the real text arriving elsewhere is how the
  writes-above-then-below bug starts.
- **The keyboard is an inset, not a resize**: the bands re-partition, and lifting the whole shell
  cannot work (it would push the strip off the top).
- **Tool rows are volatile and never persisted**; sources persist. The durable evidence of what an
  answer stands on is the sources.
- **Source chips have no favicons and make no network request** — a favicon would leak the domains
  the user searched. Proved by a source check, not by a promise.
- **Numbers that are chosen are labelled chosen** in the code, never dressed as derived ones.
- **The proof regime**: there is no render harness (`testEnvironment: node`, `testMatch
  **/*.test.ts`, no `react-test-renderer`, no testing-library). Arithmetic and decisions live in
  pure modules with tests; pixels are proved by screenshots; source-level rules are proved by
  checks that read the files and prove themselves non-vacuous.

## What was tried and failed — do not repeat these

- **An audit in `plan` mode produced nothing**: the auditor could not run bash, so it could not
  recompute anything. Audits must be able to execute.
- **Auditing a moving tree produced ghosts.** Commit first, then audit the frozen sha.
- **A Reviewer launched without `auto_accept: true`** interrupts with a permission request per
  command. Materialise every field of the profile.
- **`--max-workers=2` does not cap the NDK**: AGP invokes `ninja -C <dir> <targets>` with no `-j`,
  and the CI recipe's `CMAKE_BUILD_PARALLEL_LEVEL`/`NINJAFLAGS` are no-ops for the same reason. 21
  concurrent `clang` flattened the machine. The fix is not a cap: **turn the C++ build off** with
  `-PrnllamaBuildFromSource=false` (a CLI `-P` outranks `android/gradle.properties:65`, which the
  Expo plugin sets to true). `KALSA_LLAMA_FROM_SOURCE=0` throws at prebuild, so it can only turn it
  on; `-PrnllamaHexagon=false` has no consumers and is decorative.
- **Two emulators at once flatten the Mac.** The owner's words: "un emulatore per volta".
- **`git checkout -- <file>` on an uncommitted fix reverts the fix.** Copy to `/tmp` first.
- **A tap zone under the status bar is unreachable** — the status bar's touchable region sits above
  the app window. The preview's size cycle is on the strip's `+` instead.
- **`uiautomator dump` cannot run while the cloud animates** ("could not get idle state"): read
  bounds with animations off, restore them, then capture.

## A practical warning about this repository

**Reading whole files is what killed this session's context.** `AiChatPage.tsx` and `AppShell.tsx`
are enormous (the first is over 7000 lines). Always read with `offset`/`limit`, prefer `grep -n`
with a narrow pattern, and let an Explorer agent do the wide reading. The design documents are the
only files worth reading whole.
