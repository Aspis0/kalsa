## 3. What this session delivered

**The panel's concurrency row, and the provenance under it.** The row reads `Two devices decoding` /
`0.73x each, 1.47x together` / `Decode rate vs one device, not wall time — measured on
kalsa-server-v1.1.1, macos-arm64/metal`. The number cannot age silently: it is one constant beside
the identity of the release it was measured on, and `chat/scripts/tier-panel.mjs` compares the two
**exactly**, at the four decimals the constant carries, with the two decimals the row displays as a
separate check.

**The provenance is derived, never asserted.** `platform`, `backend` and the whole release identity
are matched by the EXECUTED binary's sha256 against `artifacts[].exe_sha256` of the published
manifest (`https://dl.kalsa.io/kalsa-server/v1.1.1/manifest.json`, whose own sha256 and fetch
instant are fields too). Three states, never conflated: `matched`; `not-the-release`, carrying §9's
label `fork build, not the release`; `unverified`, which a network failure produces and
`not-the-release` never is. Each carries a machine-readable `reason_code`.

**`Stopping`** (`6efec90`, corrections `5ffcb11`). A stop in flight is a state, not a flag, because
the outcome used to depend on two actors writing the same field. The caller declares the drain
BEFORE the command is queued — that ordering IS the window, closed from its first instant — and
`crates/kalsa-supervisor/src/drain.rs` enforces that while the state reads `Stopping` the only
writes that land are the drain's own ends. The `brain_state` arm lowers the door and the pairing
square and never raises them.

**The `Stopped` invariant** (`f1df191`, `ae78761`, `f9d8861`, `f7ac758`). `Stopped` needs both halves
and the witnesses are not interchangeable (`presence.rs::settle`): a **reaped child** is the kernel's
proof about OUR process, so the port is **not a veto** — if something answers it afterwards,
`Stopped` is still true of our engine and what answers is a suspicion **recorded**; a **known pid**
alive after both signals is a survivor whatever the port says; a known pid now dead is corroborated
by the port (§9's "pid AND port"); an **adopted-blind** engine gets `Stopped` only after the probe
FAILS, plus the record, because the port is then the only witness there is. Anything else closes the
drain as `StopUnconfirmed` with its measures. The suspicion lives beside the state file
(`<state file>.orphan`, `suspect.rs`) and the next start recovers it (port silent) or replaces it
(adoption by port and health). `child::Termination` says whether the walk needed a grace, needed
SIGKILL, or never saw the process leave; a failing `kill` is a datum.

## 5. Where the bodies are buried

- **A manifest that was READ but published no usable digest was accused of being a fork build.**
  Missing, empty, `null`, an integer and uppercase hex all produced the strong
  `fork build, not the release` label. Weak evidence was read as a verdict — the one class the
  original mutation could not catch, because that mutation tested a match that was too WIDE.
- **A check that compares at the precision it DISPLAYS is blind below it.** The panel check used
  `toFixed(2)` on both sides, so any drift under 0.005 on any of the three ratios stayed green; the
  historical red arrived only because the aggregate happened to move 0.0068.
- **A DTO declared twice drifts.** `ModelsSurface.tsx` had its own `kind` union without `"stopping"`,
  so the real DTO fell into a blind `default` and told the owner it could not tell what the computer
  was running — for the whole teardown, while the state said exactly what was happening. Fixed by
  importing the shared type and making the switch exhaustive with a `never` arm: a new kind is now a
  COMPILE error, not a false sentence.
- **A presence probe is not a readiness probe.** `health_ok` answers `false` for ANY failure —
  refused, timeout, 503 "loading", garbage — so a live but slow engine reads as absent.
  `presence.rs` exists for the distinction: NOTHING LISTENING (connection REFUSED, positive evidence
  of absence) versus SOMETHING LISTENING (connected, then answered 503, answered 200, or said
  nothing — presence either way).
- **The witnesses are not interchangeable, and that is the invariant.** A naive "pid dead AND port
  silent" would have made three existing tests red (`tests/supervisor.rs:38,106,122` — the child is
  reaped while the fixture's own `FakeHealth` still holds the port), and the cheap way out would have
  been to change the fixtures. The right answer was to make the code tell the truth: a reap is a
  proof about OUR process, the port is a separate suspicion.
- **Escalation is not failure.** A child that needs SIGKILL after ignoring SIGTERM ends CORRECTLY
  (`stop_escalates_to_sigkill_for_a_wedged_child`, `fake_stubborn.sh`). What decides `Stopped` is the
  presence, never that a grace expired — and the expiry is logged, not punished.
- **`let _ = wait_pid_gone(pid, grace)`** (`child.rs`) swallowed the second wait: a survivor after
  SIGKILL returned `Ok(())`, and `signal(pid, Kill)` ignored the `kill` error (EPERM/ESRCH). That
  `let _ =` is what §9 calls "the grace expiry recorded instead of swallowed".
- **The drain guard and the failed-to-stop end.** `drain::set` refuses every write but the drain's
  own ends while draining. A failed-to-stop is one of those ends and had to be admitted explicitly —
  otherwise the guard makes a survivor invisible, which is the lie the invariant prevents.
- **A test that binds, drops a listener and then demands REFUSED from that port is a test whose
  fixture lies.** At rest the kernel refuses every time (2000 of 2000); under socket churn the window
  opens, the connect lands on a dying or reassigned state, the probe answers `There{Silent}`, and the
  test sees a ghost. It cost 5 failures in 16 runs and a one-in-twenty-one mystery whose name a pipe
  ate. Closed by making the probe an **argument** (`presence::Probe`): policy tests inject
  `Gone`/`There`/`Unknown`, the refusal's classification is tested as a pure function of an
  `io::Error`, and only the deterministic socket cases keep a real listener.
- **A mutation script whose anchor does not match fails silently**, the assertion aborts, and the
  suite runs the UNMUTATED source: a vacuous green produced in the same session that was attacking
  vacuous greens. Make every mutation script assert it changed the file.
- **`$?` after a pipe is the pipe's exit, not the test's.** `npx tsc --noEmit | head` reported 0 for
  a run that exited 2. And `awk`-summing a suite's output ate the NAME of the one test that failed
  once: a sum is not a record.
- **The measurement gate works.** During the third run `--max-load 6.0` refused twice (load 6.6 →
  31.9, while a reviewer compiled Rust); the run waited ~9 minutes rather than raise the ceiling.
- **APFS is case-insensitive**, the engine's xdist worker 5 wants port 8130 (the app's own engine),
  and a stale engine can satisfy a health check — all three from the previous handoff still stand.

## 6. Standing rules

Unchanged from `docs/HANDOFF-2026-09-21-b.md` §7 and `docs/PLAN-DISK-TIER.md` §7. The three that did
the most work tonight:

- **Name the repository, the branch and the HEAD**, always — five repositories and two worktrees
  share names and remotes.
- **A test or a pin must be able to go red for the reason it declares, and the proof is a mutation
  that kills it** — mutated by the reviewer, not by the author's own replay. The reviewers found more
  by mutating than by reading, and one of them found a false number in a commit message.
- **Stage by name.** Never `git add -A`, never `.`, and no push, tag or release without the owner's
  explicit OK.
