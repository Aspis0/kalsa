Running a dense 4B model is generally smoother because its entire weight matrix fits comfortably within the smartphone's 8GB RAM, allowing for efficient, direct access without the overhead of managing sparse data structures. In contrast, the 35B MoE model, despite activating only 3B parameters, requires significant memory bandwidth and storage I/O to dynamically load and unload expert weights, which introduces complexity in managing the memory footprint and increases the risk of page faults as the system swaps data between RAM and the faster UFS 3.1 storage.

*   **Memory and Storage Overhead:** While the active parameters of the MoE model are small, the sheer size of the full 35B parameter model often exceeds available RAM, forcing the system to constantly stream expert weights from flash storage, which is slower than RAM and can cause bottlenecks.
