Running a 35 billion parameter Mixture-of-Experts (MoE) model on a phone with 8 GB of RAM and UFS flash storage presents significant memory management challenges. The model’s weights are far larger than the available RAM, requiring careful strategies to balance speed and capacity. We examine three distinct approaches to manage this resource constraint.

The first approach involves memory-mapping the entire model file. The operating system kernel attempts to keep frequently accessed pages in physical RAM. However, because the model exceeds available memory, the kernel must constantly swap pages in and out. This leads to frequent thrashing, where the system spends more time managing memory than computing. The second approach streams only the routed experts for each token into a limited 2 GiB Least Recently Used (LRU) cache. Dense weights are held in anonymous buffers, while expert weights are fetched on demand. This reduces the active working set but introduces high latency when experts are not in the cache. The third approach splits the workload by placing the dense trunk on the mobile GPU while keeping expert GEMMs on the CPU. This leverages the GPU’s high bandwidth for common operations but requires efficient data transfer between CPU and GPU memory, which can become a bottleneck if the transfer rate is slow.
