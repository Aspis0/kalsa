Running a 35-billion parameter Mixture-of-Experts model on a device with 8 GB of RAM and UFS storage requires careful memory management. The total model size is substantial, often exceeding 10 GB even with quantization, which means the entire model cannot fit in RAM. The system must decide how to handle the data movement between the fast flash storage and the limited working memory.

The first approach maps the entire model file into memory using memory-mapped I/O. The operating system kernel attempts to keep frequently accessed pages in RAM, but this relies entirely on the kernel’s paging algorithm. In this scenario, the whole file is logically resident, but only the hot pages are physically in RAM. A major page fault occurs when the kernel evicts a page to make room for new data, forcing a slow read from the UFS flash. This method is simple but unpredictable, as the kernel may evict critical expert weights just as they are needed.

The second approach uses a strict streaming strategy with a limited 2 GiB LRU cache. Here, only the dense, non-expert weights are held in anonymous buffers in RAM. For each token, the router selects a small subset of experts, and the system streams only those specific expert weights from flash
