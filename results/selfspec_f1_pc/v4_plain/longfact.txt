Running a 35 billion parameter Mixture-of-Experts model on a device with 8 GB of RAM and UFS storage presents significant memory constraints. The total model size typically exceeds 16 GB even with quantization, far surpassing the available RAM. Consequently, the system must manage data movement between the fast but small volatile memory and the slower, larger flash storage. The following analysis compares three distinct architectural approaches to this problem, focusing on resident memory, I/O patterns, and the implications of page faults.

First, memory-mapping the entire model file allows the operating system kernel to handle paging automatically. In this scenario, the entire model file remains on disk, and only the specific weights required for the current computation are loaded into RAM. A major page fault occurs when the kernel must read a full page from the slower UFS storage because the requested data is not in physical memory. This approach is simple to implement but suffers from high latency if the kernel cannot keep all necessary hot pages resident. Second, streaming only the routed experts into a limited 2 GiB Least Recently Used cache offers a more controlled approach. Here, dense weights are held in anonymous buffers, while expert weights are fetched dynamically. A page fault here is a deliberate miss in the application-level cache
