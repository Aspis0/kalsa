**Through the real door** (`--door-bin`, `crates/kalsa-door/examples/measure_door.rs`). The door

door's worker path) is timed against the streams. The child's stdout and stderr never reach a
message (withheld), and stderr goes to `DEVNULL` (`5e60435`).

## 4. Where the bodies are buried

- **A door-mode run that measured two paths.** The first `--door-bin` version sent B through the
  door and A and A2 **direct to the engine**, then labelled the result `via = "door"`. A smoke
  exited 0 and its bracket passed, and still the comparison was between two routes. Only reading
  the call sites found it (Reviewer A). The rule: a mode flag must be proved **per request**. The
  fake-transport test (`dev/test-door-harness.py`) drives the measured A/B/A2 sequence and asserts
  that those completions went to the door's port with a Bearer credential, no `id_slot` and no
  salt header. The pinning check before the arms sends a direct completion on purpose: it is the
  one that proves the salt namespace.
- **Tests that checked keys and not values.** The first N-stream shape test would have stayed green
  with any arithmetic. It now recomputes the committed artifact's ratios from its raw rates and
  pins the N = 4 literals.
- **A privacy test that ran on a fixture.** "No salt in door mode" was checked on a dict the test
  built itself. It now scans what the real producer builds.
- **Ctrl-C between `Popen` returning and `proc` being bound orphaned the runner.** SIGINT is
  masked across the spawn-and-assign window (`pthread_sigmask`), in both the runner spawn and the
  engine spawn.
- **Scrubbing secrets out of child output is a losing game.** Scrubbing after truncation leaked a
  cut hex tail. Grouped, spaced, split and uppercase renderings got past the scrubber. The fix was
  to stop quoting child output at all, and the scrubber is deleted. Then **not reading a pipe
  turned out to be a bug of its own**: a child that writes more than a pipe buffer to an unread
  `stderr=PIPE` blocks forever (Reviewer A forced it with 16 MiB). Output you withhold goes to
  `DEVNULL`; it does not go to a pipe nobody drains.
- **Commit agreement was looser than anyone thought.** A 7-hex prefix passed. I had declared that
  a residual, and the declaration was wrong. A 41-hex token was cut to 40 and passed too. The rule
  is now: at least 9 lowercase hex each, equal, or a prefix of a full 40. The token needs an edge
  on both sides. Both holes were found by review mutations, not by the author.
- **A unit bug that a test was built to miss.** The probe's instants were `perf_counter` seconds
  recorded under an `_ms` name (fixed in `bf2a605`). The fake probe refused sub-ms values, so the
  test could not see it. The pin now fails if a series shows no sub-0.1 fraction of its own.
- **Commit messages are claims, and three were false this session**: "12 of 12 died", "the same
  vector list" (8 against 6 at the time), and "99 (88+8−2)" (the base was 93, and 88 was an older
  count). Each one was corrected forward in a later commit message (`4b12e00`, `02335db`,
  `5e60435`), and nothing was amended. The artifacts were not affected.
- **Smokes that are not numbers.** The door smoke with A and A2 direct; `f-door4b`, taken with the
  units bug; and the N = 4 smokes taken with `--bracket-tol 1.0` while the reviewers ran their own
  engines (2.2455× door, 2.1816× direct, `A2/A` 0.9728). None of them is a result. The door smoke
  of record for the harness's plumbing is `f-door4c`.
- **`dev/measure-slot-restore.py --sizes` with a subset crashes** with
  `KeyError: 'swa_full_off_1900_salted'`, because the `answers` block hardcodes the 1900-token keys.
  The bug predates this session (it is in `76afcd4`). It fails after the whole measurement has run
  and before any artifact is written, so it costs a full run.
  It is declared here, not fixed.
- **zsh does not word-split `$c`.** `for c in "python3 x.py"; do $c; done` exits 127. Use
  `eval "$c"`. Also write the real exit code to a file (`cmd > log 2>&1; echo $?`), because a pipe
  reports the pipe's status.
- **A mutation that keeps a file's size can run the OLD bytecode.** CPython invalidates a `.pyc`
  by source mtime (to the second) and size. A mutation of the same length, written within the same
  second, can leave the stale `.pyc` in use, so the "mutated" run tests the pristine code, in either
  direction. Reviewer B saw two false reds from it. Clear `dev/__pycache__` between a mutation and
  its run. `python3 -B` alone does not cure it: it stops a `.pyc` being written, not a stale one
  being read.
- **The engine's decode rate divides by 255, not by the 256 it prints.** `print_timing` says
  `6449.02 ms / 256 tokens … 39.54 tokens per second`, and 256 / 6.44902 s is 39.70. The first
  token comes out of the prompt pass. The harness records the engine's figure; recompute it with
  255.
- **The panel's two-device spread is in git, not in prose.** The artifact was written three times,
  and `git show 5b9b98f|fe14e78|34de14f:dev/results/concurrency-two-devices/results.json` gives
  all three. Cite those commits, not the plan's sentence about them. A reviewer rightly refused a
  spread that the tree did not carry.
- **A module rebuilt under an artifact's feet.** `libllama-server-impl.dylib` in the dev build was
  rebuilt on 09-23 at 02:19, after three dev-build artifacts had been measured on 09-21, and those
  three recorded only the launcher. The module they ran is gone. Record the module, not the
  launcher (plan §5, task 4).
