## 3. What this session decided

- **The disk tier is built now** (owner's call), and it is its own plan: `docs/PLAN-DISK-TIER.md`,
  version 2, hostile-audited and corrected. Isolation stays per **device**, not per chat.
- **`--swa-full` is not a launch flag of the tier.** Measured, twice, with the harness fixed:
  the flag moves the save file's size and nothing about warmth. The ~1.4 GiB it would have cost on
  one 64k slot is not paid.
- **Identity lives in the file name, built by the door**, and the **salt does not enter the name**:
  the salt is a hash of the credential, so a re-pair would turn a name carrying it into silent data
  loss. The door builds `d<device>-m<hash8>-c<conversation>.bin` and validates the conversation id
  shape; a dot or a slash is a refusal, never a sanitisation.
- **The residency map is the door's own**, keyed by slot. Whoever says which chat was resident
  decides **which file the slot's state is written into**, so the caller never says it.
- **The slot has three states**, `Empty | Unknown | Resident(device, chat)`. On an engine that never
  answered the state is `Unknown`, the sentence says unknown and never "empty", the restore is not
  repaired, and the next activation **does not save** — it will not write out a slot's content it
  cannot name.
- **A save is staged**: it goes to `<name>.staging` and the real file is replaced **only when the
  engine reports `n_saved > 0`**; a reply without that field is unreachable, never a success. This
  is what stops a sleeping engine from writing an empty state over a real chat.
- **The webview waits for the door** before a chat becomes active. Reason: the door serialises
  pagination per slot, but **a completion does not pass that gate**, so an optimistic switch lets the
  activate's deferred erase/restore wipe the state the completion just built — losing exactly the
  warmth the tier exists to give.

## 6. Where the bodies are buried

- **The harness never sent the salt on the slot actions.** `slot_action()` called `post()` without
  `salt_hex`, so `save`/`erase`/`restore` reached the engine with no `X-Kalsa-Cache-Salt`; the
  "salted" arm meant "completion salted, slot actions unsalted", a path no client produces. **The
  door does send it** — `crates/kalsa-door/src/engine.rs:67` calls `request::private_headers`, which
  writes both headers, because the door's own call has to read as the same device.
- **A stale engine satisfies a health check.** A re-run was discarded whole because the fresh engine
  logged `couldn't bind HTTP server socket … port: 19313` and exited, while `wait_health` was
  answered by an engine left alive by an interrupted run, writing into the **previous** work
  directory. `Server.start` now refuses a port that already answers and a child that exited during
  boot. Its first version had a false positive: a port in `TIME_WAIT` is bindable by the engine and
  was not by the probe, so the probe sets `SO_REUSEADDR`.
- **A field that can lie is worse than no field.** The harness hardcoded a `blocking_mechanism`
  string naming the namespace defect; it would have been false in the run that proved the defect
  gone. It is now derived: `cold_arms`.
- **Killing a measurement needs the right pattern.** `pkill -f "llama-server --host 127.0.0.1
  --port 1931"` matches nothing, because `-m <model>` sits between the binary and `--host`. Kill by
  the binary path: `pkill -f "/kalsallama/build/bin/llama-server"`.
- **`brain` is not `main`.** The app's remote (`github.com/Aspis0/kalsa.git`) is the **phone** app's
  and holds two lineages: `origin/brain` (ours) and `origin/main` (the phone app, 911 ahead of the
  merge base). There is no local `main`. Never check it out, never push to it.
- **The app's engine holds port 8130**, and the engine's own test suite gives xdist worker 5 port
  `8080 + 5*10` = 8130 (`tools/server/tests/conftest.py:7-13`). Running that suite in parallel while
  Kalsa Brain runs produces a red that has nothing to do with the code. Serial, or with the app closed.
- **Pins must assert the exact pair, exactly once.** `contains("--ctx-checkpoints 1")` is true of
  `--ctx-checkpoints 12`, and a helper reading the first occurrence lets a duplicated flag through.
  Both were measured: a mutation left 49 plus 151 tests green before, and turns red after.
- **A neutral failure sentence must be declared, not omitted.** `failure.rs:347-360` requires an
  action word; a cause the user cannot act on joins the named `unrecoverable()` list, and the same
  test asserts an exemption does not also give advice.
- **The engine's save catch does not clear the slot; the restore's does** (`server-context.cpp:2812-2819`
  against `:2885-2889`). That is why a refused save keeps its residency and a refused restore rolls
  back.
- **T1 is in no release.** The app pins the `kalsa-server-v1.1.0` archive; `origin/b11010-merge` is
  `5c96b18dd`. A shipped disk tier needs a new engine release carrying `833cde99b`.
- **A pin can be vacuous by construction.** `a_dirty_unknown_slot_is_never_saved` took its instant
  **before** `complete(...)`, while the mark is stamped in `SlotTurn::drop`, i.e. after — so
  `now - dirty_at < QUIET` was always true and the **quiet gate short-circuited before the residency
  gate**. The `Unknown` refusal was never exercised: the three assertions would have passed against a
  `save_idle` that saved `Unknown` slots. Measured, with the residency gate mutated off: the old test
  stayed **green**, the fixed one went **red**. A green that measures nothing is the most expensive
  kind, because it gets cited as evidence.
- **A retry that feeds its own condition is a livelock, not patience.** `n_saved` is
  `slot->prompt.tokens.size()` (`server-context.cpp:2820`) and `nwrite == 0` is an **error**, not a
  200-with-0 — so `Saved::Nothing` could only come from a zero-token slot while the map said
  `Resident`. Keeping the mark and retrying each interval read as "one attempt per interval"; in fact
  every retry POSTs a `SLOT_SAVE` task, which **stamps `time_last_task`** — so at intervals under 3×
  the idle clock the engine never reaches its sleep threshold, never prints the sleep lines, and
  `invalidate_residency` never fires. Model in RAM for ever, and the loop with it. `dbe23b3` relaxes
  the map to `Unknown` instead: a mark the sweep can never name is a promise the tick can never keep.
- **APFS is case-insensitive.** A test planted `d1-mA1B2C3D4-caaaa1111.bin` as an unknown and a canary
  `d1-ma1b2c3d4-caaaa1111.bin`: they differ only in case, so here they are **one file** — the unknown
  won, `owner()` refused it (correctly) and `canary.exists()` found the same inode. Deterministically
  red, and the first coder died chasing it. Two filesystem traps now, this and port 8130.
- **A parser's assumption is enforced at its input's gate, not in the parser.** `owner()` reads the
  model as exactly eight lowercase hex; nothing in `names.rs` enforces that. `with_model_hash`
  (`crates/kalsa-door/src/lib.rs:420-427`) is the single writer of that field and refuses everything
  else with `InvalidModelHash`. Reading a parser means reading its boundary.
- **A directory named like a valid file is invisible to the sweep.** `fs::remove_file` on a directory
  fails always and the error is swallowed (`paging/sweep.rs:85`), so a directory carrying an absent
  device's name is skipped at every moment and collected never. Declared.
- **`read_dir` failing reads as an empty directory.** A missing or unreadable save directory answers
  the same as an empty one. The app refuses the launch if it cannot create it, so the path is
  unreachable today — declared, not tested.
- **A test's own claim about its value can be false.** `tests/paging_sweep.rs:5-14` claimed that
  without the negative a delete-everything sweep would pass every other test; measured, four of the
  other five catch it. The negative's unique value is rereading the **bytes**.
- **The negative is the invariant.** A sweep that deletes a present device's file is not a cleanup,
  it is data loss. The keeping test reads the file contents back, not just its existence, and the
  empty device set is **impossible by type** (`Devices::new` refuses it, `devices.rs:112-115`).
- **`total_slots` is not the door's capacity.** `door_capacity` forces **1** when the engine does not
  consume the private headers (`src-tauri/src/main.rs:178-186`), so `total_slots`, `args.parallel` and

- **`active_devices` enters before the ownership check** (`proxy.rs:189` against `:202`), so `/props`,
  `/health` and the door's own routes count. At rest with N resident chats it answers **0**; during any
  request it answers ≥1. Presence is not residency, and the difference is the whole number.
- **The engine's save/restore replies already carry the bytes.** `n_written`
  (`server-task.cpp:1628`) and `n_read` (`:1639`) exist on the wire; `paging/io.rs:96` reads **one**
  field per call (`n_saved`) and discards them, and `Slot` holds no byte count.
- **Three `n_ctx` and a fake.** The right one is `default_generation_settings.n_ctx`
  (`server-context.cpp:4939`). Decoys: `/models` `data.meta.n_ctx` (`:4889`), the `GET /slots` slot
  JSON (`:696`, refused by the door), the `EXCEED_CONTEXT_SIZE` reply (`server-task.cpp:1505`) and the
  router's `n_ctx: 0` (`server-models.cpp:1936`).
- **The per-slot window is `ctx-size / parallel`**, and `--ctx-size` is the total:
  `AdvancedDto.context_tokens` used as a per-slot window is wrong by a factor of `parallel`.
- **`nctxCache` memoizes a `null` per endpoint** and clears it only on a settings save
  (`chat/src/App.tsx:299`, `:1170`) — so fixing the fetch alone leaves the old `null`s, and that

  carry another branch's file content uncommitted (today: `kalsa-gpu-opencl-v73`), so "the engine"
  is not one tree and a build's provenance has to be stated, not assumed. `_kalsa_archive` and
  `kalsa-device-build` are archives and builds, not repositories.

- **Nothing goes upstream.** No PR, issue, comment, review, patch or discussion. Upstream is read,
  never written.
- **No push, tag or release without the owner's explicit OK.**
- **One branch per repo** — the app on `brain`, the engine on `main`. Nobody creates another.
  **A branch is not an artifact: delegate and review by commit hash.**
- **Stage by name** (`git add <file>`), never `-A` and never `.`.
- **Workflow**: Explorer (recon, no sub-agents) → the orchestrator writes the plan → a hostile audit
  → fix → delegate with Coder and Reviewer on **different models**. An errored review is a lead,
  never a pass.
- **No number reaches the user interface before it is committed in a stripped artifact.**
- **Never create a God file.** A file holds one responsibility, and the test is that you can name it
  in one phrase. Line count is a smell, not the rule: ~250 is indicative, **~350 is fine**, and a
  change that only moves lines to make a number work should stop and leave the file where it is.
  **No new file beyond ~350**, and no file — new or existing — that mixes responsibilities until it
  stops being readable. Test files follow the same logic: if a test file becomes an indistinguishable
  list of cases, split it by **topic**, not by line count. Pre-existing excess is **declared, not
  refactored**. Comments only for WHY or a trap, and if a comment declares an invariant that invariant
  must be true. No secret **values** anywhere.
- Paseo: `create_agent` wants `title` first and **`title` ≤ 60 characters**; the provider is **one
