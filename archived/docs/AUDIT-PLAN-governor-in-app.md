## Angle 5 — safety

D1. Fallback == today's CPU path: guaranteed only for PRE-LOAD refusal (fit/NoFit/no-OpenCL/profile-invalid). Governor-init failure necessarily happens AFTER two model loads (F9); falling back then requires disposing two models and reloading single-context — a new double-load path the plan never specifies. The existing `KALSA_GPU_FALLBACK` retry (LlamaService.ts:1429-1457) keys on "params.n_gpu_layers > 0" and literally cannot fire in governor mode (deviceTuning still returns cpu-only, F45), so the plan's "same load/completion behavior" is undefined for flag-on init failure. "Exactly today's CPU path" overclaims. PLAUSIBLE→gap.
D2. Sticky failure + route-by-batch structurally preclude silent half-offload (B2); NoFit default on unknown generation/KV (F25/F36) is the right conservative read. CONFIRMED for "no silent half-offload".
D3. fit refusal before load: stated and tested in S6 ("NoFit must land exactly on CPU-only behavior"); lmkd §7.18 evidence correctly used. CONFIRMED.
D4. DeviceTuning still pins Android to cpu-only ("return { kind: "cpu-only", reason: "gpu-fit-gate-blind" }", deviceTuning.ts:335-374) — today's path is genuinely CPU-only. CONFIRMED.

## Angle 6 — missing steps

E1. No correctness oracle in S5 acceptance: criteria are "TTFT ≤ CPU/3, decode ≥ CPU, zero lmkd kills" — no token/string equality between governor and single-context on device. Fork prior art exists (scratchpad PLAN.md:20-26: "byte oracle esatto … token equality vs baseline … PROVATO su DUE arch reali") but the plan points to it only for TTFT ("roughly 10x", REPORT.md:30-39, whose own gate is also TTFT/decode/commit-only). A KV-commit bug can pass every S5 cell with corrupted output. BLOCKER for S5 as written.
E2. Flash-attn + quantized-V route rejection: named as risk 4 (F34) but no S-step tests llama_governor_init failing on `llama_kv_route_query Reject` (llama-governor.cpp:51-59) → CPU fallback; engineParams' single-context remedy (v→f16) can't be assumed to transfer to a two-context init. Missing step.
E3. Android BatteryManager: no permission is required for battery temperature (sticky ACTION_BATTERY_CHANGED / BATTERY_PROPERTY_TEMPERATURE), so "no new permissions" is trivially true — but the plan never says where the "small Android BatteryManager native snapshot" lives: llama.rn's JSI is shared-library C++; reading BatteryManager needs a JNI/Java bridge, which contradicts §3's "<250-line TS module" as the whole app-side change. Also QRD8650 dev boards are typically batteryless → permanent sensor_valid=false; S7 covers "invalid/stale sensor" hostile cases but no named default policy for always-invalid sensors is defined. Missing (vagueness).
E4. thermal_zone0 on QRD boards: cited hook already degrades to memory-proxy (F29); plan inherits that fallback without stating it for the governor's t_idle/trend inputs. Minor.

## Overall verdict

Seam diagnosis, fork contract, KV/commit semantics, RAM gate provenance, and the rebase DIRECTION are all verified accurate — the reference host is exactly "two models + one governor + active-context sampling", and llama.rn's single-ctx assumptions (decode, MTP, slots, sessions, perf, JSI token conversion) are real at the cited lines. But: ~6 REFUTED citations (F2, F20, F26/partial, F32, C3, plus the F31 SoC mislabel), the S5 acceptance cell has NO correctness criterion (E1 — the only blocker-class defect), the half-offload prohibition is sound while the "exact fallback" guarantee is undefined on governor-init failure (D1), and the RAM lower bound is ~500 MiB light at the app's own n_ubatch (A5).

**APPROVE-WITH-FIXES.** Fixes required before S5: (1) add on-device greedy/byte equality governor-vs-single-context to S5 acceptance (E1); (2) define the governor-init-failure fallback (dispose two models → single reload) and drop "exactly"/"byte-for-byte" language for the flag-on case (D1); (3) recompute §4 with n_ubatch=512 terms (A5); (4) relocate the BatteryManager native home and name the batteryless-QRD default (E3); (5) correct the citation list (F2, F20, F26, F31, F32) and the 12f6d9b6d diff numbers (C3); (6) add an S-step for route-Reject → CPU (E2).
