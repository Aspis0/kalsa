## 5. KERNEL OPT (§5)

**5.1 — MAJOR — "Profile per kernel (OpenCL profiling events)" is not a capability the
llama.cpp OpenCL backend has.** The backend docs expose only kernel-cache debug
(`GGML_OPENCL_KERNEL_CACHE_DEBUG`); no `GGML_OPENCL_PROFILING`-class env exists and the queue
is not created with `CL_QUEUE_PROFILING_ENABLE` (NOT VERIFIED in source; verified absent from
published docs). Fix: budget a small instrumentation patch (enable profiling on the queue +
capture events around the q2_K/q3_K MUL_MAT_ID dispatches, env-gated) plus its build and a
device sanity run on day 4 — or profile via Qualcomm Profiler on the QDC session only. Without
this, §5's first step silently becomes "write a profiler", and Phase 3 loses a day.

**5.2 — MAJOR — the 1.2× gate is on the whole pp512 cell while the changes touch only the
MUL_MAT_ID expert GEMMs.** Experts are the bulk but not all of prefill (trunk q5/q6 dense +
attention remain); a 1.2× total requires roughly 1.3–1.5× on the kernel slice — the same
dilution that killed earlier cells. The gate should be dual: **kernel-level (prereg primary,
e.g. MUL_MAT_ID GEMM node ms ≥ 1.2×, measured with the 5.1 patch) AND cell-level ≥ 1.1×**
(N≥5 ABBA as written). Plausibility of 1.2× kernel-level on first-pass correctness-first
kernels: plausible but unproven — the only strong prior (ML Drift, ~5× prefill on Adreno 740)
comes from a fully fused executor, not incremental tiling
([arXiv 2505.00232](https://arxiv.org/html/2505.00232v1)); Qualcomm's own guidance is
format/layout-sensitive
([blog](https://developer.qualcomm.com/blog/matrix-multiply-adreno-gpus-part-1-opencl-optimization)).
The scalar-uint constraint removes the uchar/short-lane playbook but leaves uint vector
loads, register blocking and workgroup geometry (740 warp = 64, banked Vulkan probe) — enough
material for one honest pass; the plan's own §10 admission ("may simply not be reached") is
correct and should stay.

**5.3 — NOTE — GEMV/cool-mode carve-out (≥10 % to gain) is sensible** and consistent with
the M1 lesson (GEMV at DRAM ceiling 34–41 GB/s on the dominant FFN shapes — a 10 % gate will
likely fail there; that is the correct outcome).
