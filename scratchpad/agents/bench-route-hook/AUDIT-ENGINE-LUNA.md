## Findings

- **CONFIRMED — the override does not bypass safety or admission gates.** `src/llama-governor-policy.cpp:166-180` returns CPU for `CRITICAL`, `Invalid`, and `LOWBAT` before the override branches; GPU override returns GPU only when `gpu_fit == Fit`. `src/llama-governor-runtime.cpp:73-85` calls `policy_.admit_prefill(...)` and returns `-2` for `Wait`; `src/llama-governor-policy.cpp:230-254` caps rows by `n_batch` and admits the small-prompt floor only when `below_warn`. - **CONFIRMED — `auto` restores the old route decision, not byte-for-byte state/output.** `src/llama-ext.h:313-316` says “`Auto = 0` ... no override: today's plan decides”; `src/llama-governor-policy.cpp:175-183` has only CPU/GPU branches before the unchanged plan, so Auto falls through. The differential test compares the same engine, chunk string/count, route facts, and only equality of one prefill-position boolean (`tests/test-governor-bench-route.cpp:259-270`); it is not a byte-for-byte state comparison.

- **CONFIRMED — `actual` follows the context dispatch; it is not independent hardware telemetry.** `src/llama-governor.cpp:259-260` selects `ctx_decode` or `ctx_prefill` from `cpu_prefill`; `src/llama-governor.cpp:309-310` records CPU/GPU from that same boolean after decode succeeds. It does not prove GPU work ran: the host test explicitly loads with `n_gpu_layers = 0` (`tests/test-governor-bench-route.cpp:35-38`) yet verifies the logical GPU route. The app logs `prefill_ctx_ngl` separately (`/Users/marco/Projects/kalsa-wt-bench-apk/src/engine/LlamaService.ts:1860-1868`); evidence consumers should require that field to show offload.

- **CONFIRMED — `forced` means “requested mode matched,” not “the override caused this route.”** The implementation is `mode != Auto && chunk.actual == mode` (`src/llama-governor.cpp:313-316`), and the public comment defines it as “an active override whose demanded engine ran” (`src/llama-ext.h:326`). The same false causal implication occurs whenever Auto already selects the requested engine. This is not false under the narrow code comment, but it is misleading as causal evidence. Rename it `override_matched`, or make causal `forced` require that the Auto counterfactual selected a different engine and the requested engine actually ran. The app's `route_mismatch` checks only `actual != appliedMode` (`/Users/marco/Projects/kalsa-wt-bench-apk/src/engine/benchRoute.ts:163-176`), so it does not resolve that ambiguity.

- **CONFIRMED — the 64-chunk cap truncates silently.** `src/llama-governor.cpp:303-316` increments the count only while the array has capacity; `src/llama-ext.h:382-386` says overflow “keeps the first entries and stops recording.” No overflow bit or total count is surfaced. ## Ship call

The route selection and safety order are correct for the fixed measurement protocol, and the current 1024-token maximum avoids the chunk cap. I still return **NO** because the binding does not enforce the engine's no-overlap contract for its new mutable setter; an allowed concurrent call can race completion startup and make route selection nondeterministic.
