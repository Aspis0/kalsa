## ATTACK 1 — ARITHMETIC OF THE INVERSES (the specialty)

**Verdict: all five new restores are byte-exact inverses of their producers. CONFIRMED correct.**

### 1.1 Producer layout contract (cvt.cl, stated in the convert kernels, unchanged)
For block (i00,i01,i02) the 16 packed qs bytes live in 4 LE uints at
`src_q[base + w*ne01]`, `base = i02*ne00_blk*ne01*4 + i00*ne01*4 + i01`:
  word0 = bytes 0..3 = `pack_lo(qs[0..7])`   (pairs p=0..3)
  word1 = bytes 4..7 = `pack_lo(qs[8..15])`  (pairs p=4..7)
  word2 = bytes 8..11= `pack_hi(qs[0..7])`
  word3 = bytes 12..15= `pack_hi(qs[8..15])`
where `pack_lo(x0,x1) = (x0&0x0F)|((x1&0x0F)<<4)`, `pack_hi(x0,x1)=((x0&0xF0)>>4)|(x1&0xF0)`.
Converts stride: w=0 lo → word0, w=1 lo → word1, w=0 hi → word2, w=1 hi → word3 (verified in
`kernel_convert_block_{q4_0,q4_1,q5_0,q5_1,mxfp4}_trans4_ns`: `lo = q + w*stride`,
`hi = q + (2+w)*stride`, stride = ne01*4 bytes). All five producers are identical in this
respect; mxfp4 keeps the same interleave as q4_0 (documented in-kernel).

### 1.2 Restore reassembly (all five bodies are structurally identical)
`q0 = src_q[base]; q1 = src_q[base+ne01]; q2 = src_q[base+2ne01]; q3 = src_q[base+3ne01];`
`for i in 0..7: byte_shift = 8*(i&3); lo_word = i<4 ? q0 : q1; hi_word = i<4 ? q2 : q3;
 x0 = byte(i&3) of lo_word; x1 = byte(i&3) of hi_word;
 b->qs[2i]   = (x0&0x0F)|((x1&0x0F)<<4);
 b->qs[2i+1] = ((x0&0xF0)>>4)|(x1&0xF0);`

Substitution proof (x0 = pack_lo(a0,a1), x1 = pack_hi(a0,a1)):
  qs[2i]   = (x0&0x0F)|((x1&0x0F)<<4) = (a0&0x0F) | ((a0&0xF0)>>4)<<4 = a0.
  qs[2i+1] = ((x0&0xF0)>>4)|(x1&0xF0) = (a1&0x0F) | (a1&0xF0) = a1.  → EXACT.
Word/byte mapping: i<4 ⇒ byte i of word0 = pack_lo(pair i) ✓; i≥4 ⇒ byte i−4 of word1 =
pack_lo(pair i) ✓; same for hi/word2/word3 ✓. i01 stride ne01 matches producer ✓.
i00/i01/i02 strides identical (base formula identical) ✓. Loop bound QK/4 = 8 ⇒ 16 qs bytes
for every type including mxfp4 (QK_MXFP4=32) ✓.

Numerical simulation (node, literal transcription of the contract): 500,000 random blocks,
producer→new-restore round trip → **0 failures**. qh LE uint byte round-trip: 200,000 cases →
0 failures. [A1 CONFIRMED]

### 1.3 Per-type special cases
- q5_0/q5_1: qh handled by LE uint read + byte extract, byte-copied by producer at
  `dst_qh[dst_blk_offset*4 .. +3]`; round-trip LE self-consistent. qh block UNCHANGED between
  parent and target (only two comments added; verified by `git diff … | grep qh`).
- mxfp4: `b->e = src_e[src_d_offset]` where `src_e` is `__global uchar*` (E8M0), offset formula
  equals producer's `dst_e[dst_blk_offset]`. block_mxfp4 = e:1 + qs:16 = 17 bytes host-side
  (static_assert in ggml-common.h) == harness layout {17,1,16} ✓.
- int-vs-uint ids: q4_1/q5_0/q5_1 restores declare `int i00` (others `uint`). Safe: global ids
  ≥0, arithmetic otherwise identical to producers; no realistic overflow for weight tensors,
  and identical formula in producer.
- No off-by-one, no swapped lo/hi, no wrong stride found in any of the five. The class of bug
  the prompt warned about is not present at the source level.

## ATTACK 2 — BITSELECT PRODUCER VARIANT

**Verdict: bit-select arm is bit-exact equivalent to the default byte-wise arm; host plumbing correct. CONFIRMED.**

- `bitselect(a,b,c) = (a & ~c) | (b & c)` per OpenCL spec.
  - pack_lo_bs: a=(x0&0x0F), b=(x1&0x0F)<<4, c=0xF0 → (x0&0x0F) | ((x1&0x0F)<<4) ✓ (shifted value
    occupies only bits 4..7 so `b & 0xF0 == b`).
  - pack_hi_bs: a=(x0&0xF0)>>4, b=(x1&0xF0), c=0xF0 → ((x0&0xF0)>>4) | (x1&0xF0) ✓.
  - Exhaustive check over all x0,x1 ∈ [0,255] for both helpers: **0 mismatches**.
- Default (non-bitselect) arm is text-identical to the pre-commit expressions → zero behavior
  change to the default producer.
- Host selection (`load_cl_kernels`, ggml-opencl.cpp:1646-1668): value-parsed, exact strings.
  `getenv("GGML_OPENCL_CVT_VARIANT")`; `""`/`"bytewise"` → default arm; `"bitselect"` →
  `cvt_compile_opts += " -DGGML_OPENCL_CVT_BITSELECT=1"`; anything else → WARN + default.
  NOT presence-only. Appended to opts **before** `build_program_from_source(...)`, so the
  program (and every kernel created from it) is rebuilt from the embedded/read source per
  variant. One program built per process; no stale-program reuse possible; variants coexist
  across processes. [A2 CONFIRMED]
- Interplay with the pre-existing `GGML_OPENCL_CVT_OPTS` override: variant marker is appended
  after the override replaces `compile_opts`, so it survives when both are set. Not a conflicting
  build path.
- Embedding: device build embeds `cvt.cl.h`; the -D applies to whichever source string is used.
  The shipped .so demonstrably contains the marker + helper text (binary grep). [A2 ✓]

**CAVEAT (PLAUSIBLE, not a code defect):** the pre-registration byte-matrix predicts
“fixed restore + default bytewise producer ⇒ ~94,208/294,912 dirty” but “fixed restore +
bitselect producer ⇒ 0 for all five”. Because the two producers are source-BIT-identical,
a non-zero difference between the arms can only arise from the device miscompiling one helper
form and not the other — which is exactly the diagnostic the commit is designed to run, and it
is explicitly pre-registered as “re-measure”, not a bound. The “0” rows are only achievable if
the S23 compiles the bitselect arm correctly; if it miscompiles both or neither, the matrix
prediction fails (and the operator must run BOTH arms as two separate process invocations with
the env set before startup).

  (disjoint regions). Signature ternary: `exact_odd_hi_to_f` requires `n_mis≠0 && trans4 &&
  meta_ms==0 && qh_mis==0 && qs_even_mis==0 && qs_mis==qs_odd_mis && qs_mis==hi_to_f_lo_ok &&
  qs_other==0`; otherwise `"qh_or_mixed"` if qh_mis>0 else `"other"`. If a device failure were

- Model alignment: poison model = odd qs byte high nibble → 0xF while low nibble preserved

## ATTACK 6 — PRE-REGISTRATION MATH (oracle-consumer/REPORT.md § at ~1219)

**Verdict: closed-form NMSE correct; poison-event arithmetic correct; two-point calibration logic sound. CONFIRMED, with a weak-band and soft-number note.**

- q4_0: 32 values, 16 qs bytes, “8 poison-capable positions per block” = high nibble of each odd
  qs byte (value indices ≡3 mod 4). Poison ~1/2 ⇒ mutated code 0xF ⇒ value `7d`. 
  Visible mismatch condition `P(wanted hi nibble != 0xF)=15/16`:
  events=131072·(1/2)=65,536; invisible=65,536/16=4,096; visible=61,440;
  61,440/294,912 ✓ (294,912 = 16,384 blocks · 18 B; 16,384 = 256·512·4/32 ✓). Ncand=131,072 ✓;
  per-offset 16,384·15/32 = 7,680 ✓.
- NMSE: E[q²] unpoisoned = (Σ_{j=-8}^{7} j²)/16 = 344/16 = 21.5 ✓; E[δ²|poison] = E[(15−n)²] =
  1240/16 = 77.5 ✓; poisoning fraction (8/32)(1/2)=1/8 ✓ ⇒ NMSE = (1240/8)/344 = 1240/2752 =
  **0.4505813953 ✓**. Cross terms vanish under iid zero-mean activations ✓.
- f1/f2 two-point design: internally consistent as a falsifier. Poisoned-byte replay must match
  f2 and reproduce the FAIL; clean-byte replay must match f1 and PASS. If the OpenCL compute
  itself were also wrong, the clean point fails → correctly flags “second contributor”. The
  “pristine CPU judge” + independent offline implementation removes shared-bug fit. Sound.
- **Weak-band note (PLAUSIBLE):** the model is a single constant (0.45058) yet is said to be
  “inside the observed 0.36-0.70 band” and to show “no second contributor”. A wide band has weak
  discriminating power; the band test alone under-determines the conclusion — which is exactly
  why the strong two-point replay is required. Consistent, but the band statement overstates the
  falsification.
- **Intermediate-state 94,208 (PLAUSIBLE soft spot):** has no closed form; inherited from a
  measurement taken while the old restore was also broken; the pre-registration itself labels it
  soft and mandates re-measurement. Additionally, “≈94,208 dirty for bytewise” alongside “0 for
  bitselect” is only achievable if the device genuinely miscompiles the bytewise producer but
  not the bitselect one (the two produce identical bytes by construction — see A2 caveat). This
  is the experiment's premise, not a regression in the code.
