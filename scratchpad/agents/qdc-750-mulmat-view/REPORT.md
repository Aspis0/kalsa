## 3. What this establishes

- Baseline reproduced the 20 FAIL with `GGML_HEXAGON=OFF`, satisfying step 0: [PREREG.md:L31-L33] “The baseline must reproduce the 20 FAIL with this build configuration”; [raw/sa811910/summary.tsv:L1] “baseline 12f6d9b tbo_mm 905 20 1 114”; [raw/sa811910/12f6d9b_tbo_mm_view_counts.txt:L2] “fail=20”.
- Candidate turned all 20 into PASS: [raw/sa811910/summary.tsv:L5] “candidate 2f3b24d tbo_mm 925 0 0 113”; [raw/sa811910/2f3b24d_tbo_mm_view_counts.txt:L4] “family_fail=0”; MUL_MAT_ID stayed 407/407 [raw/sa811910/2f3b24d_tbo_mmid.out:L843] “407/407 tests passed” and FA stayed 226/226 [raw/sa811910/summary.tsv:L7] “candidate 2f3b24d tbo_fa 226 0 0 33”; bench deltas were +0.19% and −2.21%, within the preregistered ±10% guard [PREREG.md:L50-L51] “within ±10%”.
- This is a workaround gate: [ANALYSIS-f16-l4.md:L50] “Chosen fix: gate all Adreno F16/F32 specialized selection when src0 is non-contiguous and use the generic `kernel_mul_mat_f16_f32`.” Amendment 2 says [PREREG.md:L78] “remains **unexplained** (the l4_y8 kernel is stride-aware)” / [PREREG.md:L79] “The gate is a workaround with a falsifiable prediction, not a root-cause fix.”
- The cherry-pick is inert for this family because it is quantized-only: [PREREG.md:L59] “but its broadcast/view change is **quantized-only**: the Adreno path normalises BF16 to F16” / [PREREG.md:L60] “and then excludes F16/F32” / [PREREG.md:L61] “For the failing shape (m=128, n=1, k=1056, r2=4) the C++ dispatch selects `kernel_mul_mat_f16_f32_l4_y8`”; [PREREG.md:L64] “H1 as-is is REFUTED — the 20 FAIL will persist with the bare cherry-pick.” The candidate includes it [PREREG.md:L85] “Candidate kit = 12f6d9b6d + c7ad97025 (cherry-pick, inert for f16)” / [PREREG.md:L86] “+ 2f3b24dee (gate).”; pick-only effect is not isolated by this test—one tested variable is the combined pick+gate (“not in raw”).
