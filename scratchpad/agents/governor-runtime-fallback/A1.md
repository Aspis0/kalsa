### The decision (pure, jest-reachable)

`shouldRuntimeGovernorFallback({ error, isLocalTurn, aborted, fallbackUsedForModel })`
is true only when all four hold: message starts with the exact JSI prefix
`Governor decode failed: ` (verified against the installed binding:

`governorRuntimeFallbackReason` returns the text after the prefix (the log-line

### The wiring (LlamaService.ts, file:line as committed)

- State: `lastLoadArgs` :348, `runtimeGovernorState` :360 — tri-state
  `"fresh" | "fallback-reload" | "fallback-consumed"`. One runtime fallback per
  loaded model; the governor stays off until the **next explicit load** (any
  `initEngine` call that is not the fallback's own reload moves the state back
  to `"fresh"`, :2231).
- Catch: :5483–5502. Abort branch runs first (unchanged behaviour), then the
  decision at :5489 with `isLocalTurn: !isRemoteEngineBackend()` (leaf module
  `remote/remoteSettings.ts`, no cycle; `engineBackend.ts` dispatches Brain
  turns to `streamRemoteAssistantTurn`, so a Brain turn never reaches this
  catch — the parameter still refuses a mid-turn backend switch). On true it
  returns the reason instead of calling `emitEngineError`.
- Reload: `.then` continuation :5537–5555 → `reloadGovernorRuntimeFallback`
  :2797–2816. **The reload runs outside the engine job on purpose:**
  `disposeEngineLocked` awaits the engine-job chain (`LlamaService.ts:2846`)
  and the failing turn *is* a running job — reloading from inside the catch
  would wait on itself until the 60 s safety timeout and mark the context hung
  (`DISPOSE_SAFETY_TIMEOUT_MS`, :578). Exactly one log line is emitted there:
  `KALSA_GOVERNOR_RUNTIME_FALLBACK {"reason":"governor is failed"}` — prefix
  match + text after the prefix, no prompt/model text.
- CPU-only path: the helper arms `"fallback-reload"` and calls `initEngine`
  with the stored args minus `sessionRestore` (governor mode never wrote a
  `.kvs` this session — save skip verified at :3218 and :5628; a stale file
  must not seed the retry, so the turn re-prefills cold, accepted). `initEngine`
  transitions the state at :2231, refuses the idempotent skip (`!governorRuntimeOff`,
  :2383), and routes `initWithGovernorFallback({ enabled: !governorRuntimeOff })`
  :2576 → the existing `cpuParams` block (:2572-2575: governor/speculative
  deleted, `n_gpu_layers = 0`, `n_parallel = 1`). `governorUsed = !governorRuntimeOff
  && !result.retried` :2584 keeps the governor bookkeeping truthful, and
  `KALSA_NATIVE_VARIANT` now reports 0 layers for this reload.
- Retry: recursion into `streamAssistantTurn(messages, callbacks, signal, options)`
  :5555. History lives in JS and travels by value (`messages` → `currentMessages`
  at the completion call), so the user message is not appended a second time.
  Per-attempt state (accumulators, cleaners, timers, `finishOnce`, the abort
  listener) is declared inside the job, so the retry starts clean; the failed
  partial is discarded because every `onDelta` carries the full replacement text
  (`engineCallbackBridge.ts:48-51` → AppShell `assistantFull = full`), and the
  retry's first emission replaces the bubble. If the retry fails, its catch finds
  the state off `"fresh"`, the decision is false, and `emitEngineError` surfaces
  the error exactly as today. No new UI copy, no new settings; the existing
  busy state covers the reload.
- Termination: the helper moves the state out of `"fresh"` before `initEngine`,
  so the decision can never hand back a second reason — the continuation cannot
  recurse twice. If the reload itself throws, it is surfaced through
  `emitEngineError` and the turn ends.

## Round 5

Found by reading `b8219c88` on disk (no audit round): `!modelStillLoaded`
returned `"stale"`, and stale calls no callbacks — so a model pick during the
reload ("Continue" while streaming, `selectModel` without abort) with no

**Fix.** Only `!turnStillCurrent` means `"stale"` (no callbacks — a newer
turn owns the UI). The cause is renamed `"retry" | "stale" | "ended"`:
`"ended"` — the turn is still current but cannot continue (signal aborted,
or the model changed under it) — clears the partial (`onDelta("", "")`) and

ended (`governorRuntime.ts`; rule and rename stated in the docstring). The
continuation routes both gates through `endCurrentTurn()`
(`LlamaService.ts`): pre-reload a model change ends the turn and skips the
reload (reloading would arm CPU-only state against the wrong model); a
superseded turn returns with no callbacks at either gate.
