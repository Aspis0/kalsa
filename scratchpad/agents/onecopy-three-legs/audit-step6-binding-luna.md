## Findings

1. **P1 — CONFIRMED — Teardown frees the process-wide OpenCL import cache while other contexts may still use it.** `cpp/rn-llama.cpp:154` — `    release_opencl_imports();` This runs on every `loadModel` teardown (`:1325`), including ordinary reloads; the engine API clears every cached import, not just this owner’s. JSI loads/completions run on multiple worker threads, and an OpenCL compute can have obtained a cached `cl_mem` before release and enqueue after `clFinish`, leaving a concurrent use of a released handle. **Fix:** make import lifetime owner-scoped, or serialize release against all OpenCL access through completion of enqueue/use.

2. **P1 — CONFIRMED — Shared-weights mode and the 832 MiB cap leak into later loads.** `cpp/rn-llama.cpp:229-231` — `    const ggml_hexagon_shared_weights shared_weights {` / `        true, k_onecopy_shared_mbuf_bytes };` / `    if (set_shared_weights(&shared_weights) != 0) {` The setter changes backend-global `opt_hostbuf`, `opt_hostbuf_repack`, and `opt_mbuf`; no binding path restores them. A later normal or two-model load—including after `KALSA_HTP_FALLBACK`—therefore gets different buffer placement/cap, disproving byte-identical two-model behavior across reloads. **Fix:** save and restore the prior global settings after the last shared buffer is freed.

3. **P1 — CONFIRMED — The global setter is unsynchronized with concurrent model loads.** `cpp/rn-llama.cpp:231` — `    if (set_shared_weights(&shared_weights) != 0) {` The engine setter contract says its option fields are unsynchronized and requires caller serialization; the binding takes no process-wide load lock. `createPromiseTask` runs tasks on the multi-worker `ThreadPool` (`cpp/jsi/JSIUtils.cpp:69`), so another context can construct/load a model while these backend globals change. **Fix:** serialize the setter and every model/context initialization that reads those globals with one process-wide lock.

4. **P1 — CONFIRMED — One-copy overrides the caller’s NPU kill switch and readability verdicts.** `cpp/rn-llama.cpp:310-312` — `    policy_params.npu_lane_enabled = true;` / `    policy_params.htp_trunk_readable = true;` / `    policy_params.htp_experts_readable = true;` The capability-row branch is taken without checking `governor_params.npu_lane_enabled`; parsing defaults that field to false, and the historical path only resolves the HTP lane when it is true (`:398-416`). A caller that disabled HTP (including for failed fit/readability checks) is forced onto NPU anyway. **Fix:** preserve the caller’s lane gate and use the historical two-model path when it is off; do not synthesize readability facts from the hardware row.

5. **P1 — CONFIRMED — A present GPU context is treated as proof that the required HOST weight was admitted.** `cpp/rn-governor.cpp:48` — `        if (llama_governor_leg_ctx(governor_, legs[i].engine) == nullptr) {` This only checks context existence. The engine’s OpenCL HOST admission also depends on a real buffer import and the tied Q6_K self-check; a failed admission can make the scheduler decline that op to CPU while the binding keeps the one-copy governor and GPU leg. That violates J(1)/R2’s “NPU-shared only with OpenCL HOST” invariant. **Fix:** require an explicit successful admission result for the actual tied Q6_K output weight before accepting one-copy; otherwise tear down and use the two-model path.

6. **P2 — CONFIRMED — The GPU fact gate can validate a different, non-Adreno-740 device than the `GPUOpenCL` backend uses.** `cpp/rn-legs-table.cpp:127-128` — `                if (clGetDeviceIDs(platform, CL_DEVICE_TYPE_GPU, 1, &device,` / `                                   nullptr) != CL_SUCCESS) {` The reader always takes the first GPU on the first platform and breaks, while the backend honors `GGML_OPENCL_PLATFORM` / `GGML_OPENCL_DEVICE`. Separately, the table’s `gpu_model_token` is only `"740"` (`:63`), so the boundary helper does not require a Qualcomm Adreno identity. **Fix:** read facts from the selected `GPUOpenCL` device and match the exact Adreno model/vendor plus compiler line.

7. **P2 — CONFIRMED — Recoverable one-copy leg/load failures abort instead of using the legacy load.** `cpp/rn-llama.cpp:378-379` — `            case onecopy_load_result::failed:` / `                return false;` Once the setter succeeds, model-load or governor/leg initialization failures are classified `failed`, so `load_governor_models` never tries the existing two-model branch even when that branch could load. A GPU-leg refusal is precisely a case where the required three-leg configuration is unavailable. **Fix:** after teardown, demote recoverable one-copy model/leg admission failures to the historical two-model loader.

8. **P2 — CONFIRMED — TTS embedding batches bypass governor routing and mutate only the prefill leg.** `cpp/rn-llama.cpp:329` — `    owner.ctx = owner.governor->prefill_ctx();` `cpp/rn-completion.cpp:1646` — `            const int rc = llama_decode(parent_ctx->ctx, b);` The ordinary path routes through `parent_ctx->decode()` (`rn-completion.cpp:1711`), but the TTS embedding paths call `llama_decode` directly; governor mode does not reject TTS. These writes bypass the governor’s leg routing/KV bookkeeping. **Fix:** send TTS batches through the governor decode wrapper or reject TTS when governor mode is active.
