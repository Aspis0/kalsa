# SESSION-IDENTITY-RECON-2026-09-10 (read-only, repo main 3ca6145)

## Q1 — what the .kvs is bound to

Stem = `sessionStem(modelId, conversationId, promptEnvHash)` (sessionKey.ts:37-46, `${model}__${conv}__${env}` via activeSessionStem, LlamaService.ts:314-324). SessionMeta sidecar (AsyncStorage `kalsa.session.meta.<stem>`, sessionPersistence.ts:127-128) carries the rest. Verdicts:

- **BOUND — model id**: in the stem itself (`sanitizeSessionSegment(modelId)`, sessionKey.ts:40); a different model → different file, old file orphaned. No sha/quant binding anywhere in the meta (grep digest|sha256|quant|gguf in sessionPersistence.ts: zero hits) — a re-downloaded or re-quantized GGUF under the SAME model id reuses the stem. Engine knobs are pinned separately: `engineKnob: JSON.stringify of bench EngineOverride` (sessionPersistence.ts:26-28, compared in sessionMetaMismatchField :407 "engineKnob").
- **BOUND — conversation**: meta check `if (aConv !== bConv) return "conversationId";` (:413-415).
- **BOUND — prompt env (locale, memory facts, hasTools, sorted tool names, blockFormat)**: computePromptEnvHash hashes exactly `{locale, memoryFactsJoined, hasTools, tools, blockFormat}` (sessionPersistence.ts:357-372); meta mismatch `if (a.promptEnvHash !== b.promptEnvHash) return "promptEnvHash";` (:404) → load refused, artifacts deleted (`deleteSessionArtifacts(loadStem)` on repro failure, LlamaService.ts:2522-2526).
- **BOUND — history prefix**: boot hash + prefix check at load (`historyWindowReproducesKv(bootMessages.slice(0, prefixCount))`, LlamaService.ts:2521-2526) and `if (a.historyHash !== b.historyHash) return "historyHash";` (:403).
- **BOUND — engine shape**: `nCtx / cacheTypeK / cacheTypeV / mtpNMax / specType / formatVersion` all compared with named mismatch reasons (sessionPersistence.ts:398-407).
- **BOUND — memory facts WHEN on the system prompt**: env hash includes facts only when `!MEMORY_FACTS_ON_USER_TAIL` (AppShell.tsx:3781-3791); with the flag on (true, ttftFlags.ts:23) facts ride the last user tail and are deliberately EXCLUDED from the hash (:3781 comment "cold-starts the entire KV prefix").
- **UNBOUND — quantization / GGUF file identity**: no sizeBytes/sha/quant field in SessionMeta (sessionPersistence.ts:19-72); same model id with a different file loads the old KV against new weights — silent mismatch possible after a re-download that keeps the id.
- **UNBOUND — engine/fork pin**: the `kalsa-native-patches` systemInfo marker (LlamaService.ts:1294-1298, :1807-1815) is returned to AppShell but never stored in SessionMeta nor compared at load; a new APK shipping new native patches would happily restore an old .kvs (n_batch/threads/etc. are not in meta either, though they don't change the cache layout; n_ctx is bound).
- **UNBOUND — chat template exact bytes**: blockFormat (the operative block format id) is hashed (:365-371) but the actual template text of the model (llama.rn getFormattedChat) is not hashed; a model/template update with unchanged locale/tools/facts passes the env check. Partially mitigated by historyHash being over the *formatted-message-shape contract* only via BAKE_FORMAT_B_USER_PREFIX tails (LlamaService.ts:3080-3093), not template output.
- **App update (new APK, same dir)**: protected by formatVersion + engineKnob + promptEnvHash + historyHash checks; NOT by native-patch version, llama.cpp version, or model file digest — a restore can load "ok" with mismatched native state semantics.
- **Model switch**: stem carries the old model id; switch loads a different stem (or none) — `restoreEngineSession` re-checks `activeModelId !== modelId` (LlamaService.ts:2617). Old .kvs stays on disk per conversation+env (cleanup only on failed restore for the same stem, :2525).

## Q2 — invalidation observability

- **Reuse is measured per round**: `emitTurnTelemetry(turnId, round, result, …)` (LlamaService.ts:3461) → turnTelemetry.ts:119 `tokensCached: number; // result.tokens_cached` and :171 `tokensCached: result.tokens_cached ?? 0`, plus `promptMs` (:177) and `tokensEvaluated` (:120) — KALSA_TELEMETRY lines show reused-vs-re-prefilled every round. Load-side: KALSA_KVDIAG `{n_past, tokens_on_disk, ok}` (LlamaService.ts:2403-2407, sessionPersistence.ts:78-90) and KALSA_SESSION {op:"load", ok, tokens…} (:2389).
- **Explicit invalidation logging EXISTS at load** (all refusals are named: `meta_mismatch:<field>`, `tokens_loaded:0`, `no_meta` — :2506-2545) and **at prewarm** (`logPrewarm({ match: false, reason: … "prefix_miss" })` when `turnPrefixHash !== prewarmPrefixHash`, LlamaService.ts:3090-3103). What does NOT exist: a mid-conversation invalidation line when memory facts change between turns of a live KV (env hash is only consulted at save/restore, not per turn); a facts change with MEMORY_FACTS_ON_USER_TAIL only shows up as a slightly longer last-user message (tail tokens), which is the design.
- **Facts position — CONFIRMED safe by default**: `MEMORY_FACTS_ON_USER_TAIL = true` (ttftFlags.ts:23); facts are appended to the LAST USER message (`applyMemoryFactsToLastUser(currentMessages, factsTail)`, LlamaService.ts:3126-3130), NOT the system prompt; the legacy system-prompt path is behind `if (!MEMORY_FACTS_ON_USER_TAIL)` (:477-484, memoryPrompt.ts:3 "Memory facts live in the system prompt"). So an extraction adding a fact does NOT invalidate the shared prefix — it only changes the turn tail; the env hash is computed with `[]` facts in that mode (AppShell.tsx:3781-3791) so the session file is not cold-started either. The dangerous ordering (facts at top of system prompt) exists only behind the off flag.

## Q3 — LFM2.5 hybrid state

- **CONFIRMED: full memory state, not KV-only.** saveSession → `llama_state_save_file(ctx->active_ctx(), path, session_tokens.data(), save_size)` (node_modules/llama.rn/cpp/jsi/JSISession.h:178); loadSession → `llama_state_load_file(...)` (:61-63). llama_state_save/load_file serializes the whole memory tree — for LFM2.5 the hybrid memory (conv state + attention KV) is included via llama-memory-hybrid.cpp (present in the tree). Load-side guards: `llama_model_is_recurrent(ctx->model)` / `llama_model_is_hybrid` checked (:83-85) and `resumable` requires `pos_max + 1 == n_tokens` (:76-79); non-resumable → `llama_memory_seq_rm(kv, 0, 0, -1); embd.clear();` (:111-112) — the "restore ok but reuse nothing" failure mode (ggml-org/llama.cpp#25913) is guarded: JS sees `tokens_loaded:0` → `log(false, { reason: "tokens_loaded:0" }); return false;` (LlamaService.ts:2534-2538), artifacts deleted.
- **Kalsa patch #2 explicitly targets the recurrent-restore gap**: after a successful load, `ctx->completion->probeStateCache(); ctx->completion->captureStateCheckpoint(embd, embd.size());` (JSISession.h:126-131) registers the restored memory as a state checkpoint so loadPrompt's prefix search can adopt it — the comment cites the measured `n_past=0` failure on Xiaomi 14 / CI 31293842336.
- **Observability**: KALSA_KVRESUME logs `n_tokens/pos_max/is_recurrent/is_hybrid/n_swa/resumable` (JSISession.h:109-111) and KALSA_KVDIAG carries `tokens_on_disk` (sessionPersistence.ts:78-90); KALSA_SESSION load includes `tokens` (restoreNativeSession logging) and the recon claim "Jelly tokensCached growing after reopen" is consistent with KALSA_TELEMETRY `tokensCached` (turnTelemetry.ts:119,171) after the first post-restore turn. What that PROVES: memory restored and the next prefix matched (n_common ≥ prefix length once). What it does NOT prove: repeated open/save cycles stay lossless (recurrent-state drift would show only as quality/continuity anomalies, not in tokensCached), nor that `captureStateCheckpoint`-adopted state survives a SECOND close/open cycle (the checkpoint list is in-process; the second reopen relies on the same file path).

## Defects / gaps to fix first (ranked)

1. **Model-file identity unbound** (Q1): same model id after a re-download with a different quant/sha silently loads an old .kvs. Fix: add `modelSizeBytes`+`fileSha256` (already available in ModelDownloader digest) to SessionMeta and one line to sessionMetaMismatchField. Blast radius: meta-only, old files become mismatch → delete-on-refuse already implemented.
2. **No invalidation log on live-prefix change** (Q2): a facts/tool/template change mid-session is visible only via promptMs drift. Fix: in streamAssistantTurn, log `KALSA_PREFIX {reason:"facts_changed"|"tools_changed", oldHash,newHash}` when the turn's env/prefix hash differs from the previous turn's. Blast radius: one log line, no behavior.
3. **Engine/fork pin absent** (Q1): app update with new native patches can restore stale state. Fix: include the `systemInfo` "kalsa-native-patches" marker (already captured at init, LlamaService.ts:1813-1814) as an optional SessionMeta field compared with the existing mismatch machinery. Blast radius: meta-only; old files cold-start once.
4. **Q2 residual: MEMORY_FACTS_ON_USER_TAIL=false path puts facts in the system prompt** (memoryPrompt.ts:42) — every extraction invalidates the whole prefix in that mode. Fix: none needed while the flag is true; add a test pinning the flag + env-hash shape so a flip is deliberate. Blast radius: test-only.
5. **Recurrent-restore measurement** (Q3): tokensCached growth proves one reuse; add tokensCached to the settled KALSA_SESSION load line (currently only in KALSA_KVDIAG) so field logs directly show n_common per reopen without grepping two lines. Blast radius: one field.
