# Audit: `e8c8886` — 2026-09-13

Commit audited: `e8c8886e57a8f36269d499c7be538b23631d3d15` on `main`.

Verdict: **FIX**

The completion accounting is mostly correct. The change is not ship-safe because the idle predicate still excludes model lifecycle/native work, and the wipe decision is a stale snapshot that can race session restore. The new tests do not exercise either path.

### 10. Clear failure is recorded as success — PLAUSIBLE

```ts
// src/engine/LlamaService.ts:950-957
try {
  await context.clearCache();
} catch {
  // best-effort; the following prewarm still evals the new prefix
}
markChatKvCleared();
```

If `clearCache()` rejects, `markChatKvCleared()` still asserts that native chat KV is gone. The following prewarm can then run against unknown KV state. “Best effort” is not enough for a state transition that controls future KV protection.

## Bottom line

`nativeEngineWorkInFlight()` is not TDZ-broken, and tracked think/prefill/decode work is covered. The patch still needs fixing before ship: serialize/recheck the wipe against restore/lifecycle state, include loading/model-switch/native-op work in the idle gate, and add runtime integration tests plus CI coverage for the actual harness.
