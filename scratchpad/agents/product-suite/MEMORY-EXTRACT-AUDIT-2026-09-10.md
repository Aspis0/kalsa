## BUGS (Angle 3)

5. **CONFIRMED — stopReason precedence correct everywhere:** post-completion `if (abortedBySend) … else if (timedOut) … else parse` (:4152-4157) and catch `if (abortedBySend) … else if (timedOut)` (:4166-4167) — abort beats timeout, matching intent; "done" only on clean path.
6. **REFUTED — timer leak:** single `timer` cleared unconditionally in finally (:4175 `if (timer) clearTimeout(timer);`); armed only on the non-aborted path; abort-before-arm leaves timer null.
7. **REFUTED — listener leak:** `signal?.addEventListener("abort", onAbort, { once: true })` (:4075) removed in finally (:4177-4179 try/catch). If the skip branch runs, the listener was never added.
8. **CONFIRMED (the one real product bug): n_predict 128 can silently truncate the JSON.** EXTRACT_MEMORY_N_PREDICT = 128 (LlamaService.ts:447); parser caps are add ≤3×120 chars + remove ≤10×120 (parseMemoryExtract :4207-4220) — worst legit payload ≈1.6-2 KB ≈ 400-500 tokens ≫ 128. Truncated output → `findBalancedJsonObject` (:3886-3917, balanced-scan, string-aware) finds no closed object → parseOutcome 2 → facts silently dropped with stopReason "done". The recon recommended n_predict ≈160-192 for exactly this; 128 makes the drop MORE likely than the old 256 for `remove`-heavy answers. Bounded-JSON claim itself holds (no garbage apply), but "done"+parseOutcome 2 is a silent miss the telemetry cannot distinguish from a genuine no-facts turn.
9. **CONFIRMED (gap): stop/clearChat does NOT cancel extraction.** `memoryExtractCancelRef.current?.()` is invoked only from the send path (AppShell.tsx:4999). clearChat/stop aborts the send signal → `onAbortRelease` releases the gate, but the extractionAbortController is never aborted there; if extraction already started (gate released, then clearChat), the extract runs to its (now up to 120 s) timeout while the user waits on the NEXT send that awaits `memoryExtractRef`. Old code had the same shape at 20 s; the budget increase widens the window 6×. Intent (3) says "a new user send aborts" — stop/clearChat is not a send; gap is real but arguably out of scope.
10. **REFUTED — unhandled rejections:** extractJob is awaited by the next send (:4933) and tracked via trackMemoryExtractJob's finally; inner try/catch returns; no floating promise except `void preparation`-style patterns already audited.
