- **CONFIRMED — destination-ahead trim/recommit is correct, including the recurrent side.** `commit_side()` detects `dst_end > end`, calls `trim_sequence(end)`, rechecks, then copies `[src.watermark, end)` (`src/llama-governor.cpp:97-124`). The hybrid commit copies attention first and then recurrent tensors plus cell/head/index metadata (`src/llama-hybrid-commit.cpp:57-86`). A scratch-only LFM probe forced a hybrid destination at 32 tokens against a one-token source, requiring the no-rollback full clear/recommit (`n_rs_seq=0` by default, `src/llama-context.cpp:3669-3676`); fresh-context logits matched exactly (`max_diff=0`). Sabotaging the trim made that probe fail with the expected `(32 > 1)` route reject (EXIT=1).

- **CONFIRMED — supported rewind keeps the equal-length prefix valid.** Binding prompt reuse restores/rewinds the active cache, then calls `governor->trim_sequence(n_past)` (`cpp/rn-completion.cpp:673-683`). That API trims both contexts and adjusts both watermarks; when a hybrid side cannot roll back, it is cleared and the next required route catch-up or phase handoff copies the surviving rewound side from position 0. A strict `p_end > d_end` check does not detect arbitrary equal-length content divergence, but equal-length divergence is not produced by these supported operations: successful commits establish a shared prefix, rewinds touch both sides, and `clear_cache` clears both. A raw one-context `seq_rm` that bypasses the governor remains unsupported.
