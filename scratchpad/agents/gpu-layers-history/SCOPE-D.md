## Per-question verdicts

1. **GPU layer count set or swept — EVIDENCE EXISTS.** Four independent cells: `q44-ngl-sweep-mem` (0/7/13/19/99, driver `results/ngl_sweep_s23/device/kalsa_q44/driver.sh:414`), `gpu_prefill_recheck_xiaomi` (8/16/24/99, driver `results/gpu_prefill_recheck_xiaomi/run_part2.sh:92`), `olmoe_gpu_moe_s23` (4/8/12/16), `qdc-8g2-npu-mmapbudget-60` (8/12/99, QDC board, NPU not Adreno); plus partial-offload crash arms in `oomwall` (ngl 0/2/8) and `-ncmoe 99` trunk/expert splits in `q16-xiaomi`.

2. **Memory-fit refusal / OOM / rpcmem pressure on a real phone — EVIDENCE EXISTS.** Today's own event is banked verbatim at `scratchpad/agents/governor-nofit-prefill/REPORT.md:16` and `:22`; a real device-matched fit refusal (Qwen 4B, `refusedBy:"fit"`, `MemAvailable 3640.3 MiB`) at `scratchpad/agents/xiaomi-ram-zram-investigation/REPORT.md:157-160`; a full-GPU allocation that **kernel-rebooted** the Xiaomi at `scratchpad/agents/q16-xiaomi/REPORT.md:404` with `MemAvailable 6704924 kB`; and hard power-offs on the S23 at `scratchpad/agents/oomwall/REPORT.md:17`. No rpcmem allocation-failure dump was found — the only rpcmem line is allocator setup, `results/ttft_4b_xiaomi/manual_1a/logcat_send_oom.txt:5463`.

3. **Measured GPU memory footprint per layer/leg — EVIDENCE EXISTS (Adreno 740 only).** `q44-ngl-sweep-mem` is a real per-layer accounting: 1 Hz device-side sampler over `MemAvailable/MemFree/SwapFree` + `VmRSS/RssAnon/RssFile/VmSwap` (`driver.sh:88`), `GGML_OPENCL_LOG_ALLOC=1` for real `OPENCL_SET_TENSOR` bytes, giving k per ngl point (`REPORT.md:48-54`) and the affine `800 MiB + 1.05×bytes` fit (`REPORT.md:77-85`). **Zero** driver-side GPU bytes: KGSL per-pid node unreadable, `gpumem` NA on every point (`REPORT.md:95`). No smaps or `dumpsys meminfo` methodology was used in any cell I read.

4. **Device / condition / comparability — DONE, see table.** Only **one** cell paired layer count with memory: `q44`, on **S23 / Adreno 740, unplugged, llama-bench CLI, LFM2.5-8B-KEXP**. The **only** SM8650 / Adreno 750 layer ladder is `gpu_prefill_recheck_xiaomi` — **Xiaomi 14 phone, unplugged, 2026-08-18, llama-bench CLI, Qwen3.5-2B-Q4_K_M** — and it recorded **speed only**. All `qdc-*` cells are **QDC boards: speed-indicative, heat-meaningless**. The closest *in-app* harness (`s23-layers-device-proof`) is S23 and varies NPU↔GPU, not layer count.

5. **Partial GPU offload tried / rejected / left untried — EVIDENCE EXISTS, all three states.** *Tried and crashed:* `oomwall` W1 `-ngl 2` → POWER OFF (`REPORT.md:17`); Xiaomi `-ngl 99` Marco → kernel reboot (`q16-xiaomi/REPORT.md:404`). *Tried and lived:* `qdc-8g2-npu-mmapbudget-60:38` (HTP ngl 8/12, prefill **and** decode). *Tried and speed-rejected:* `gpu_prefill_recheck_xiaomi/report.md:178` ("ngl 8 ≈ CPU ... ## What I could NOT verify

- **No layer count × memory matrix on SM8650 exists anywhere in my four trees.** The two halves exist on different devices: memory-vs-layer-count on the S23/740 (`q44`), layer-count speed on the Xiaomi/750 (`run_part2.sh:92`). `results/gpu_prefill_recheck_xiaomi/cells/` holds 286 files and **none** is meminfo/smaps/rpcmem/kgsl — I listed and grepped it; `run_part2.sh` contains no memory sampling at all.
- **Whether `800 MiB + 1.05 × offloaded_bytes` is right on the Xiaomi.** The constant is fitted on one S23 sweep with one model; `q44-ngl-sweep-mem/REPORT.md:85` itself says "to be validated on a second model/device before trusting the constants". Today's `available_mib 3004.93` is being compared against a constant that has never touched SM8650.
- **Whether a partial Adreno offload on the Xiaomi fits at 3004.93 MiB.** Never run. No `n_gpu_layers` value between 1 and 98 appears in any Xiaomi artifact I read.
