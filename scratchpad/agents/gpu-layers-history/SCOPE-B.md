## Per-question verdicts

1. **Partial GPU layer set / sweep over layer counts — NO EVIDENCE FOUND.** Every GPU layer count in both files is 0 or all (`-ngl 0`, `-ngl 99`, `0/31`, `31/31`): the archive varies *legs/backends* and *graph splits* (197→198→62 splits, `PLAN:1687`, `:1698`), never "the GPU carries N of M layers".
2. **Memory-fit refusal history — EVIDENCE EXISTS (`PLAN-2026-10-09-full.md:973-975`, `:983-984`, `:958-959`, `:991`, `:946`).** A fit gate said `Fit` against a process-lifetime-cached 3458.93 MiB with 123 MB really free, and the failure response is the `n_gpu_layers = 0` fallback; `laneFit` also returns `NoFit` for an unknown SoC even with 18.9 GB free.
3. **Measured GPU memory footprint — EVIDENCE EXISTS (`PLAN-2026-10-09-full.md:1452-1453`, `:1905-1908`; `ALIVE-2026-10-09-full.md:981-984`, `:1059`).** Per-backend buffer sizes (1306/220/205 MiB) and whole-app PSS via `dumpsys meminfo`, plus a 1.98 GB ceiling that splits a tile block into 827 + 479 MiB — but **no per-layer** figure exists.
4. **Explicit "GPU is all-or-nothing" rule — PARTIAL / NOT STATED AS A RULE.** The behaviour is consistently binary and the *reason* given is device admission, not a layer decision: the Adreno 740/E031.41 gate admits or refuses the whole GPU leg (`PLAN:1484-1485`, `ALIVE:1064`), and the `n_gpu_layers = 0` fallback is the only documented reaction to a failed fit (`PLAN:946`). No sentence in either file states "GPU must be all layers".
5. **Bench arm / lever that sets a GPU layer count explicitly — EVIDENCE EXISTS but only at the two extremes (`PLAN-2026-10-09-full.md:1115`, `:1451`, `:590`).** `-ngl 99 -fa 1` and `-ngl 99 -dev HTP0` ran on the S23 / M1 Max; `-ngl 0` ran on the M1 Max desktop. I found **no** `-ngl N` with an intermediate N, and therefore **no** record of such a sweep on an unplugged phone or on QDC.
6. **Superseded / reversed about GPU layers — EVIDENCE EXISTS (`PLAN-2026-10-09-full.md:1094-1095`, `:659-662`, `:1635-1643`, `:1687-1700`).** (a) The `n_gpu_layers = 0` site was unguarded, made iOS run 0/31, then was made Android-only — but that same fallback is still the app's answer to a failed GPU fit. (b) LEVERS.md row-2 "push prefill to CPU at MODERATE" was REFUTED by heat data; the CPU is the hottest leg on both chips. (c) "the lm_head did NOT go to the GPU" (compute buffer 0 MiB, 2026-10-05 15:35) was reversed two hours later after `offload_op` work (0.50 MiB, `PLAN:1643`).
