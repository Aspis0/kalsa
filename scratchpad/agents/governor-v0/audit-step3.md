## Angle 1 — Offset math vs state_write_data (the numbers)

- **K row math: CONFIRMED byte-identical.** Commit llama-kv-commit.cpp:98 `const size_t k_size_row = ggml_row_size(src_k->type, src.hparams.n_embd_k_gqa(src_layer.il));`, copy :101-102 `copy_tensor(src_k, dst_k, range.first * k_size_row, range.first * k_size_row, range_size * k_size_row, scratch)`. Original state_write_data (kv-cache.cpp:2180, :2186-2187): `const uint64_t k_size_row = ggml_row_size(k->type, n_embd_k_gqa);` and `io.write_tensor(k, range.first * k_size_row, buf_size);` with :2185 `const size_t buf_size = range_size * k_size_row;`. Same formula, same multiplication order, same cell-range iteration. Comment in commit :85-87 names the mirror source ("K rows use range.first * row_size").
- **Quantized K / partial ranges: REFUTED as a corruption risk.** Both implementations quantize the *cell* space, not the element space: ranges are CELL ranges (whole rows), so the byte quantum is always `ggml_row_size(type, n_embd_k_gqa)` — which rounds up to whole blocks for q4_0/q8_0 KV — and every offset is `cell_idx * row_size`, i.e. a whole-row offset. A p0 mid-block is irrelevant: there is no sub-row copy anywhere. The block-alignment hazard would only exist if the code copied element ranges of a quantized tensor; it does not. (Same reasoning as state IO, which has served quantized KV forever.)
- **V non-transposed (flash-attn): CONFIRMED identical.** :124 `v_size_row = ggml_row_size(src_v->type, src.hparams.n_embd_v_gqa(src_layer.il))`, :127-128 same `range.first * v_size_row / range_size * v_size_row` as kv-cache.cpp:2206/:2213-2214.
- **V transposed (non-FA): CONFIRMED byte-identical multiplication order.** Commit :149-155: `const size_t v_size_el = ggml_type_size(src_v->type); const uint32_t n_embd_v_gqa = src.hparams.n_embd_v_gqa(src_layer.il); ... const size_t offset = (range.first + j * kv_size) * v_size_el;` with `kv_size = src_cells.size()` (:134) and j-outer/range-inner loop order. Original kv-cache.cpp:2236 `const size_t src_offset = (range.first + j * kv_size) * v_size_el;` with :2218 `const uint32_t kv_size = cells.size();`, same j-outer/range-inner order (:2242-2250). The claimed source lines 2156-2253 are accurate (state_write_data spans :2156-2253 in the current file).
- **MLA (no V): CONFIRMED clean.** :118-123 / :143-148: `if (!src_v || !dst_v) { if (src_v != dst_v) { return false; } continue; }` — both-null (MLA) skips the layer; one-sided null is a hard failure. State IO just `continue`s on `!v` (kv-cache.cpp:2197/:2226) without the mismatch check — commit is strictly stricter.
- **CONFIRMED DEFECT — per-layer embedding-dim guard missing from `compatible()`.** :8-20 checks kv_size, cache_type_k/v, n_seq_max, n_stream, n_pad, n_swa, swa_type, v_trans, n_layer_all, layers.size() — but NOT `n_embd_k_gqa`/`n_embd_v_gqa` per layer. Yet the copy derives row widths from **src** (`src.hparams.n_embd_k_gqa(...)` :98, `src.hparams.n_embd_v_gqa(...)` :124/:150) and applies them to **both** tensors (dst_offset == src_offset :101/:127/:155). Two different models with equal kv_size/types/layer counts but different head dims pass `compatible()` → route MirrorAndCopy → `ggml_backend_tensor_set` writes src-width rows into a narrower dst tensor → OOB write (bound-checked abort in ggml, or backend corruption). Harmless for the governor's same-GGUF-twice usage, but `llama_kv_route_query` is public API (llama-ext.h). Fix: compare per-layer `layers[i].k->ne[0]` / `v->ne[0]` in `compatible()` or `aliases()` — the tensors are right there.
- Minor: state IO writes all K layers first, then all V layers (:2176-2214 then :2215+); commit preserves that K-then-V ordering (:88-106 then :108-161). Irrelevant for correctness (disjoint writes), noted for mirror-fidelity.

## Angle 2 — Cell indexing vs position range

- **CONFIRMED: no `cell index == position` assumption — the mapping is metadata-driven.** collect_ranges (:42-66) scans all cells and selects by `!cells.is_empty(i) && cells.seq_has(i, seq_id) && cells.pos_in(i, p0, p1)` (:52), closing ranges on gaps (:57-60 `} else if (begin != cells.size()) { ranges.emplace_back(begin, i); begin = cells.size(); }`). Holes from seq_rm produce disjoint ranges; multi-seq interleaving is filtered by seq_has. This mirrors state IO exactly: kv-cache.cpp:2021 `cell_ranges_t cr { s, {} };` + :2035 `add_cell = add_cell && (seq_id == -1 || cells.seq_has(i, seq_id));` with the same pos-bound filtering. The plan's fear (index==position) is REFUTED by the code.
- **CONFIRMED: `pos_in` is `[p0, p1)`** (llama-kv-cells.h:386-389 `return pos[i] >= p0 && pos[i] < p1;`) — same half-open convention as the rest of the API.
- **PLAUSIBLE API-convention hazard: p1 == -1 is rejected, not treated as "to the end".** collect_ranges :45 `if (seq_id < 0 || ... || p0 < 0 || p1 < p0) { return false; }` — a caller following llama.cpp convention (seq_rm/seq_cp treat p1<0 as "to max") would pass p1=-1 and get a silent false from mirror → commit returns false with no dedicated message. llama-ext.h must document that p1 is absolute (check below, angle 8).
- **CONFIRMED: dst metadata writes maintain all cell invariants.** :191-198 `if (!dst_cells.is_empty(i)) { dst_cells.rm(i); } dst_cells.set(i, src_cells.cp(i, 1));` — `rm()` (llama-kv-cells.h:222-233) resets `shift[i] = 0;` (:230) and the seq_pos index; `set()` (:T-range) does `seq_pos_rm` before overwrite and `seq_pos_add` after, and asserts `shift[idx] == 0` — the rm-before-set pattern keeps RoPE-delta state and seq_pos bookkeeping coherent. `cp(i, 1)` (cells.h:120-135) is a verbatim single-cell copy (pos+ext+seq, asserts shift==0) — **no seq remapping** (my initial suspicion, refuted by the signature).
- **CONFIRMED: source shift guard.** :179 `if (src_cells.get_shift(i) != 0 || ...)` — committing from a cache with pending K-shift is refused (shifted tensor data wouldn't match the copied positions). Destination-side pending shift on an overwritten cell is cleaned by rm()'s `shift[i] = 0` — net-consistent.
- **Head bookkeeping: CONFIRMED coherent.** :199-205 zeroes dst v_heads and rescans to the first empty cell (wrapping to 0 if full) — matches prepare()'s search-start semantics; harmless while the decode fence stands.

## Angle 3 — Stream index / multi-stream

- **CONFIRMED correct.** Commit resolves each cache's own mapping: :173-174 `const uint32_t src_stream = src.seq_to_stream[seq_id]; const uint32_t dst_stream = dst.seq_to_stream[seq_id];` and selects per-stream tensor VIEWS: :96-97 `const auto * src_k = src_layer.k_stream[src_stream]; auto * dst_k = dst_layer.k_stream[dst_stream];` (same for V :116-117/:141-142). The views already embed the stream base offset (kv-cache.cpp:261 `k_stream.push_back(has_k ? ggml_view_2d(ctx, k, n_embd_k_gqa, kv_size, k->nb[1], s*k->nb[2]) : nullptr);`), so `range.first * k_size_row` is stream-relative — exactly how state IO addresses `layer.k_stream[cr.strm]` (:2172/:2194/:2224).
- Cross-stream commit (src seq→stream 1, dst seq→stream 0) copies the right data by construction; `compatible()` guarantees equal per-stream geometry (n_stream, n_pad, kv_size). The `k_stream.size() <= src_stream` / `<= dst_stream` bounds checks (:91-92/:113-114/:138-139) cover the non-unified stream-count edge.
- **Note: iswa/hybrid are rejected wholesale** — `get_cache` dynamic_casts to plain `llama_kv_cache` (:210-216), so `llama_kv_route_query` on an iSWA memory returns Reject via the `!dst || !src` path (:221-223). Fine for step-3 scope (plan §3.6 covers hybrid later).

## Angle 4 — The friend escape hatch

- **CONFIRMED minimal surface, declared not inherited.** llama-kv-cache.h delta: `friend struct llama_kv_commit_access;` in the private section (+forward decl `struct llama_kv_commit_access;` at the top). No header mutation beyond the friendship — llama-kv-commit.h is just `#pragma once` + `#include "llama-ext.h"`.
- What the friend actually touches (all in llama-kv-commit.cpp): reads private `cache_type_k/v, n_seq_max, n_stream, n_pad, n_swa, swa_type, v_trans, layers, v_cells, v_heads, seq_to_stream, hparams` (:8-20, :49, :96-97, :108, :173-176) and **mutates only `dst.v_cells` (:193-197 rm/set) and `dst.v_heads` (:199-205)**. That mutation IS the commit semantic — it bypasses the step-2 seq-op fences by design, as the privilege-d writer. It does not call fenced ops (no seq_rm/clear/init_*), does not touch src (const ref :166), does not resize cells, does not free buffers.
- **CONFIRMED: the friend cannot break the cell invariants it writes** — verified in angle 2 (rm resets shift+seq_pos, set maintains seq_pos_add/rm and asserts shift==0; cp(i,1) is verbatim).
- **PLAUSIBLE residual risk:** the friend is namespace-free `struct llama_kv_commit_access` in llama-kv-commit.cpp — any future code inside that translation unit can touch private cache state through it. Acceptable for one dedicated .cpp; would be weaker if the struct grew.

## Angle 5 — Route query honesty

- **CONFIRMED: aliasing test is identity-based, not type-based.** :22-28 `same_host_tensor`: `return dst->buffer && dst->buffer == src->buffer && dst->data == src->data && ggml_backend_buffer_is_host(dst->buffer);` — same buffer OBJECT + same data pointer + host-resident. Two different buffers with coincidentally equal base pointers fail the `dst->buffer == src->buffer` identity test → no false positive from that corner. Same buffer but different tensor offsets → `dst->data != src->data` → MirrorAndCopy (safe, copy still correct). Per-layer pairing enforced in `aliases()` :32-38 (`dst.layers[i].il != src.layers[i].il || !same_host_tensor(k) || !same_host_tensor(v)` → false) — an aliased-wrong-layer pairing is rejected. Both-null V (MLA): `if (!dst || !src) return dst == src;` (:23-25) → true, correctly treating absence as "already shared".
- **CONFIRMED: Reject conditions mirror the step-2 ctor guards, not a drifted copy.** compatible() :8-19 covers exactly the ctor's seven throw conditions (kv_size, type_k/v, n_seq_max/n_stream, n_pad/n_swa/swa_type/v_trans, n_layer_all) plus layers.size(). It deliberately has NO `if (share)` override branch (the ctor's kv_size override for aliased sharing) — correct, since MirrorAndCopy requires matched sizes; an aliased pair that needed the ctor's kv_size override still routes Direct via `aliases()`... wait: if the ctor overrode kv_size for an aliased pair, both caches END with equal sizes, so compatible() passes. Consistent.
- **CONFIRMED gap (already flagged angle 1): per-layer K/V embedding dims are not compared** — same-model pairs are fine; cross-model pairs with equal coarse geometry but different head dims route as MirrorAndCopy and the copy writes with src-side widths. Public-API guard gap.
- **CONFIRMED: Direct path's unguarded assumption.** :244-247 `if (route == llama_kv_route::Direct) { LLAMA_LOG_INFO("%s: direct route already aliases K/V tensors; no copy\n", __func__); return true; }` — Direct returns true WITHOUT checking that the two caches share cell metadata (`dst.v_cells_impl == src.v_cells_impl`). Today, tensor-aliased pairs (GEMMA4 share callback) always share cells by construction, so the assumption holds; but nothing enforces it. If a future construction aliases tensors without sharing cells, commit on the Direct route is a silent no-op that reports success without moving any metadata. Cheap fix: require `&dst.v_cells_impl == &src.v_cells_impl` (or a cells-identity check) before Direct.
- Minor: Direct path ignores seq_id/p0/p1 entirely — correct iff cells are shared; another reason to assert cells identity.

## Angle 6 — Error paths

- **CONFIRMED: copy failures are undetectable by construction.** copy_tensor :74-77: `scratch.resize(size); ggml_backend_tensor_get(src, scratch.data(), src_offset, size); ggml_backend_tensor_set(dst, scratch.data(), dst_offset, size); return true;` — ggml's tensor_get/set are **void** (ggml-backend.h:86-89 show the async variants `GGML_API void ggml_backend_tensor_set_async/get_async...`; the sync API used here is likewise void). So the only `return false` paths in copy_data are null/mismatched streams (:91-94, :113-115, :138-140), NOT IO errors. A device-level failure mid-layer leaves dst half-written and the function reports success. No comment, no marker, no dst-status flag. At minimum this deserves a doc note on llama_kv_commit (llama-ext.h has none); ideally a layer-level ordering that keeps metadata (:191-198) written only AFTER all tensor copies — which it already does (metadata is set after copy_data returns true, :188-198). So the failure window leaves tensor data stale but METADATA unwritten — dst cells stay empty, a subsequent commit can repair. That's actually a defensible design; it's just undocumented.
- **CONFIRMED scratch sizing is correct but naive.** `std::vector<uint8_t> scratch;` (:83) resized per copy to the chunk size (K: range_size × row_size, V-trans: range_size × el_size). Largest allocation = largest range × row width — always sufficient. Perf nit: resize per copy instead of one max-size reserve; irrelevant at governor scale, and the plan explicitly targets byte-exactness first.

## Angle 7 — Test quality

- **CONFIRMED: the oracle covers V (including transposed V).** same_state :59-67 compares full `llama_state_seq_get_size` + byte-equal `llama_state_seq_get_data` blobs. The state format serializes K for all layers AND V for all layers (both branches of state_write_data, kv-cache.cpp:2176-2253) plus cell metadata. stories15M with default non-FA contexts ⇒ v_trans=true ⇒ the transposed-V strided path (:133-160) is exercised by the byte compare. `governor_commit_full_state=PASS bytes=41712` (my run).
- **CONFIRMED: sub-range reconstruction would catch offset bugs — symmetric cancellation is implausible.** :92-94 commits [2,n−1), then [0,2), then [n−1,n) onto an empty ctx_sub, then same_state vs ctx_a. A symmetric constant-offset bug δ (same wrong offset for get and set) yields ctx_sub[c] = ctx_a[c+δ] → mismatch. A per-range base error (range treated as starting at 0) shifts content → mismatch. A j-slice stride error (wrong `j * kv_size`) → mismatch. The commit ORDER ([2,n−1) first) additionally catches any "commit clears cells outside its range" bug: a later commit's wipe would leave the earlier ranges empty in the final byte-compare. The union of the three ranges is exactly [0,n), so metadata byte-compare matches too.
- **Minor coverage gaps (parked):** (a) the three ranges cover all of [0,n) — a range with a HOLE left uncommitted would additionally prove uncommitted cells stay empty in both metadata and state; (b) no Direct-route test possible with stories15M (GEMMA4 aliasing untested in CI); (c) no test for p1=−1 or Reject-on-commit (only Reject-on-query); (d) no test that commit from B→A (reverse direction) works — the plan's step-4 reverse commit.
- **CONFIRMED: negative test reaches the query itself.** ctx_bad = `make_context(model.get(), GGML_TYPE_F32)` (:74) created WITHOUT ctx_other, so no ctor throw; :99-102 `if (llama_kv_route_query(ctx_bad.get(), ctx_a.get()) != llama_kv_route::Reject)` exercises compatible()'s cache_type_k check inside the query. Output: `governor_commit_reject_mismatched_type=PASS` (my run).

No C ABI pretension, no macros, nothing mutating in a header.

## Overall verdict

**FIX-FIRST** — one CONFIRMED guard gap that matters the moment this stops being a same-GGUF harness: `compatible()` compares coarse geometry but not per-layer `n_embd_k_gqa`/`n_embd_v_gqa`, and the copy derives ALL widths from src and applies them to dst (commit.cpp:98/:124/:150 with dst_offset==src_offset) — a cross-model pair with equal kv_size/types/layer-count but different head dims routes as MirrorAndCopy and OOB-writes the dst tensors. Two-line fix in `compatible()`/`aliases()` (compare `layers[i].k->ne[0]` / `v->ne[0]`). Second, cheaper item bundled in: the Direct route should assert shared cell metadata (`&dst.v_cells_impl == &src.v_cells_impl`) before returning true (:244-247). The offset math itself — the plan's primary audit target — is CONFIRMED byte-identical to state_write_data on all four paths (K, quantized-K partial ranges, V non-trans, V transposed with exact multiplication order), the position→cell mapping is metadata-driven (no index==position assumption), stream handling mirrors state IO, and the test oracle is genuinely strong. Everything else is parked documentation hardening (p1=−1 convention, failure semantics).
